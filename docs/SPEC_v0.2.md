# 1. 제품 정의

> **개정 (2026-07-31, D-033/D-037/D-038)**: 이 절은 피벗으로 재작성됐다. 이전 판은
> 집중을 유일한 성장 입력으로 규정했고, 그 문장이 게임 전체를 세션에 묶었다. 현재
> 제품은 아이들 클리커이며 집중은 선택적 증폭기다. 피벗 이전 판은
> `pomodoro-v1-focus-blocking` 브랜치와 `pre-pivot-v1` 태그에 보존돼 있다.

## 1.1 한 줄 정의

**DeepMine은 암반을 부수며 광산을 아래로 넓혀가는 채굴 게임이고, 원하면 방해 앱을 실제로
차단해 생산을 증폭할 수 있다.**

## 1.2 정체성 선언

- 이건 **아이들 클리커**다. 앱을 닫아도 기계가 계속 캔다.
- 성장 입력은 둘이다. **자동 생산이 기본**이고 **집중은 선택적 증폭기**다.
- Screen Time 권한을 주지 않아도 게임은 완결된다. 권한은 더 좋게 만들 뿐 필수가 아니다.
- 방해 앱을 실제로 차단할 수 있는 아이들 게임은 없다. 이것이 유일한 차별점이며,
  토대가 아니라 기능으로 유지한다.
- 숫자를 굴리는 대상은 **부순 암반과 그 위에 쌓은 기계**다.

## 1.3 핵심 루프

```text
암반을 탭해 데미지
→ 세그먼트 파괴, 광석 획득
→ 장비 구매로 자동 데미지 증가
→ 앱을 닫아도 광석 누적 (오프라인)
→ 심도 상한을 넘어 새 지층
→ 불안정한 핵에서 붕괴(프레스티지)
→ 영구 연구로 더 빠르게 재시작
```

선택적 증폭 루프:

```text
깊은 집중 시작 (선택)
→ 방해 앱 차단, Live Activity에 진행 표시
→ 그동안 생산 배율 적용
→ AlarmKit 알람으로 종료
→ 증폭된 수확 수령
```

증폭 루프를 한 번도 쓰지 않아도 위의 핵심 루프만으로 게임이 성립해야 한다. 이것이
증폭기 설계의 판정 기준이다.

# 2. 집중 검증 — 차단 기반

## 2.1 원칙

감지가 아니라 **차단**한다. 감시당하는 느낌 대신 "갱도에 들어가면 문이 닫힌다"는 규칙감을 준다.

## 2.2 구현

- `FamilyControls`로 사용자가 방해 앱/카테고리를 직접 선택 (`FamilyActivityPicker`)
- 세션 시작 시 `ManagedSettingsStore`로 shield 적용
- 세션 종료 또는 중도 포기 시 shield 해제
- `DeviceActivityMonitor` 익스텐션의 `intervalDidStart` / `intervalDidEnd`로 세션 경계 보강

> **entitlement**: `com.apple.developer.family-controls` (Individual). Apple에 별도 신청 필요, 승인까지 수 주. **프로젝트 착수와 동시에 신청**한다. 크리티컬 패스.

## 2.3 세 단계 검증 등급

| 등급 | 조건 | 보상 |
|---|---|---|
| 봉인 채굴 | 차단 목록 활성 + shield 유지 | ×1.00 (기준) |
| 개방 채굴 | 차단 미설정 / 권한 거부 | ×0.75, "검증 배지" 미획득 |
| 붕괴 | 세션 중 shield 강제 해제 | 심층 갱도면 보상 0, 그 외 50% |

폴백을 벌이 아니라 **등급**으로 표현해서, entitlement 미승인 상태에서도 제품이 출시 가능하도록 한다.

## 2.4 시간 조작 방어

- `Date()`와 `mach_continuous_time()` 기반 경과시간을 **동시 기록·교차 검증**
- 두 값의 차이가 임계 초과 시 해당 세션은 개방 채굴 등급으로 강등
- 기기 재부팅으로 단조 시계가 리셋되는 경우는 정상 처리(강등 없음, 대신 벽시계 기준 채택)

# 3. 세션과 채굴 계획

## 3.1 세션 길이

| 세션 | 길이 보정 |
|---|---:|
| 15분 | ×1.00 |
| 25분 | ×1.10 |
| 50분 | ×1.30 |

v0.1의 10분을 15분으로 올린다. 10분은 차단 세팅 비용 대비 보상이 낮다.

## 3.2 채굴 계획 (신규 · 핵심 차별화)

시작 버튼을 **시간 선택이 아니라 전략 선택**으로 만든다.

| 계획 | 보상 | 광맥 확률 | 중도 이탈 시 |
|---|---:|---:|---|
| 안전 갱도 | ×1.0 | 기본 | 경과분 50% 지급 |
| 심층 갱도 | ×1.6 | 기본 | **전액 소실 + 스트릭 유지 실패** |
| 탐사 갱도 | ×0.8 | ×3.0 | 경과분 50% 지급 |

- 심층 갱도는 최초 3세션 완료 후 해금 (첫 사용자를 태우지 않는다)
- 계획 선택은 1탭, 기본값은 직전 선택 유지

## 3.3 세션 상태

```swift
enum SessionPhase: String, Codable {
    case preparing
    case mining
    case completed
    case abandoned
}

enum MinePlan: String, Codable {
    case safe, deep, survey
}
```

`rareFound`는 삭제한다. 사유는 §6.

# 4. 경제 시스템

## 4.1 자원

| 자원 | 역할 |
|---|---|
| 광석 | 일반 업그레이드 |
| 수정 | 희귀 업그레이드, 테마 해금 |
| 핵 조각 | 프레스티지 영구 성장 |

## 4.2 보상식 (세션 카운트 기반)

```text
세션 보상 =
    기본채굴량
  × 성장계수 ^ min(누적 집중 크레딧, 20)
  × 세션길이보정
  × 채굴계획배율
  × 검증등급배율
  × 일일스트릭배율
  × 장비배율
  × 광맥배율
  × 피로도계수
```

- `기본채굴량` = 100
- `성장계수` = **1.04** (튜닝 범위 1.03~1.05)
- 세션 20회 지점에서 체감 약 2.2배가 나오면 적정
- 구현 보정(2026-07-29): 집중 크레딧은 `완료 집중분 ÷ 25`이며 성장 지수는 20에서 상한을 둔다. 30일 시뮬레이션에서 무제한 누적 지수가 경제를 폭발시킨 결과를 반영했다. 프레스티지 후에도 lifetime 기준 상한 배율은 유지된다.

## 4.3 일일 소프트캡 (광맥 피로도)

| 당일 누적 집중 | 피로도계수 |
|---|---:|
| 0~240분 | ×1.00 |
| 240~360분 | ×0.50 |
| 360분 초과 | ×0.25 |

- UI에서는 **"광맥이 지쳤습니다 · 자정에 회복"**으로 표현
- 패널티 문구를 쓰지 않는다. 과사용 유도 제품이 되지 않기 위한 장치이자, 인플레 통제 수단

## 4.4 장비 가격

```text
가격 = 기본가격 × 1.38^(레벨-1)
```

| 레벨 | 드릴 가격 |
|---:|---:|
| 1 → 2 | 100 |
| 2 → 3 | 138 |
| 3 → 4 | 190 |
| 4 → 5 | 262 |
| 5 → 6 | 362 |

## 4.5 심도

심도는 **완료 세션 수의 함수**다.

```text
심도(m) = floor( 12 × 누적세션수 ^ 1.15 )
```

심도 증가로 해금되는 것: 광산 테마, 광맥 종류, 장비 레벨 상한, 프레스티지 구간.

# 5. 장비

| 장비 | 효과 |
|---|---|
| 드릴 | 기본 채굴량 증가 (가장 자주 강화) |
| 카트 | 긴 세션 보정 증가 |
| 램프 | 희귀 광맥 확률 증가 |

## 5.1 추천 강화

자동 실행하지 않는다. 종료 화면과 Dynamic Island Expanded에 **추천 1개 + 수락 버튼**만 노출한다.

```text
효율 = 생산 증가량 ÷ 업그레이드 비용
동률이면 드릴 우선
```

```text
[추천: 드릴 → LV.9  1,400]   [앱에서 고르기]
```

# 6. 희귀 광맥 — 종료 시 공개

## 6.1 왜 세션 중에 표시하지 않는가

앱이 백그라운드에서 suspend되면 Live Activity를 갱신할 수 없다. 세션 중간에 "✨발견"으로 Dynamic Island를 바꾸려면 (a) 푸시 서버 또는 (b) 사용자를 방해하는 알림이 필요하다. 둘 다 제품 원칙에 어긋난다.

따라서 **광맥 판정은 세션 종료 시점에 일괄 수행하고 결과도 그때 공개**한다. 세션 중에는 어떤 이벤트도 발생하지 않는다. 이것은 제약을 수용한 결과가 아니라, "집중을 절대 방해하지 않는다"는 원칙의 직접 구현이다.

## 6.2 종류

| 광맥 | 효과 |
|---|---|
| 푸른 광맥 | 세션 보상 ×1.5 |
| 수정 광맥 | 수정 획득 |
| 고대 금고 | 테마 또는 장식 해금 |
| 공명층 | 다음 세션 보상 ×2 |
| 심연 균열 | 심도 추가 증가 |

## 6.3 연출

종료 시 `staleDate` 전환으로 잠금화면·DI가 완료 상태로 바뀌고, 광맥이 있으면 그 상태에 함께 표시된다. 상세 연출은 앱 진입 시.

# 7. 스트릭 (v0.1 콤보 대체)

## 7.1 일일 목표 스트릭

- 사용자가 하루 목표를 설정 (기본 100분)
- 목표 달성 시 그날의 **연속 일수 +1**

| 연속 일수 | 배율 |
|---:|---:|
| 1 | ×1.00 |
| 3 | ×1.10 |
| 7 | ×1.25 |
| 14 | ×1.40 |
| 30 | ×1.60 |

## 7.2 유예

- 주 1회 "휴광일" 자동 소모 → 하루 놓쳐도 스트릭 유지
- 유예 소진 후 실패 시 연속 일수는 **0이 아니라 절반**으로 감소

현실 일정과 싸우지 않는다. 스트릭이 벌칙이 되면 이탈한다.

## 7.3 세션 내 배율

세션 단위 콤보(10분 내 재시작)는 **폐기**한다. 대신 당일 N번째 세션에 소폭 보너스만 준다.

| 당일 N번째 | 보정 |
|---:|---:|
| 1 | ×1.00 |
| 2 | ×1.05 |
| 3+ | ×1.10 |

# 8. 프레스티지

```text
심도 목표 도달
→ 광석·장비 초기화
→ 핵 조각 획득
→ 영구 보너스
```

- 1회차 목표: 누적 40세션 부근 (일반 사용자 기준 7~10일)
- 이후 회차는 필요 세션 수 ×1.6씩 증가
- 핵 조각 투자처 3종: 굴착 기억(기본 채굴량) / 공명 탐지(광맥 확률) / 압축 시간(긴 세션 보정)

# 9. 표시 계층 설계

## 9.1 역할 분담

| 표면 | 역할 | 표현력 |
|---|---|---|
| **StandBy** | 세션 중 주 무대. 픽셀 아트 풀샷 | 높음 (전체화면 가로) |
| **잠금화면 LA** | 기본 상태 확인 | 중간 (최대 160pt 높이) |
| **Dynamic Island Expanded** | 종료 후 강화·재시작 | 중간 (371×144pt) |
| **Dynamic Island Compact** | 상시 확인 | 낮음 (좌우 각 52~62×37pt) |
| **제어 센터 컨트롤** | 세션 시작 진입점 | — |
| **홈 위젯** | 시작 + 오늘 진행률 | 중간 |
| **Apple Watch** | LA 미러링 (자동) | 낮음 |

## 9.2 StandBy 제약 (설계 시 반드시 반영)

- 진입 조건: **충전 중 + 가로 + 정지**. 거치대가 없는 사용자는 아예 못 봄
- 상시 점등은 **Always-On 디스플레이 탑재 기기(14 Pro 이상)** 에서만. 그 외에는 20초 후 소등
- 어두운 곳에서는 **Night Mode 적색 단색**으로 전환됨 → 컬러에 의존하는 아트는 무너진다. **명도 대비만으로 읽히는 픽셀 아트**로 설계할 것
- 갱신 제약은 잠금화면과 동일. 화면만 클 뿐 실시간 갱신 능력이 늘어나지는 않는다

## 9.3 Dynamic Island 실측 규격

| 영역 | 크기 |
|---|---|
| Compact leading / trailing | 각 52pt(Pro) ~ 62pt(Pro Max) × 37pt |
| Minimal | 지름 37pt (최대 45pt) |
| Expanded | 폭 371pt, 높이 최대 144pt |
| 잠금화면 LA | 높이 160pt 초과 시 시스템이 잘라냄 |
| 아이콘 권장 | 24pt |
| 텍스트 | 15pt / 행간 22 |

## 9.4 화면 정의

### Compact — 채굴 중
```text
[⛏ 픽셀 24pt]  [센서]  [18:42]
```
좌: 계획별 광부 스프라이트 / 우: `Text(timerInterval:)` 자동 카운트다운

### Compact — 완료 (staleDate 이후)
```text
[📦 픽셀 24pt]  [센서]  [READY]
```

### Expanded — 진행 중 (371×144pt 이내)
```text
┌──────────────────────────────────────┐
│ 심층 갱도 · 148m              18:42  │
│ ▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░  (timerInterval) │
│ 예상 1,500          [포기]    [열기]  │
└──────────────────────────────────────┘
```

### Expanded — 완료
```text
┌──────────────────────────────────────┐
│ 채굴 완료            푸른 광맥 ×1.5   │
│           + 2,850                    │
│ [드릴 →LV.9]   [25분]      [50분]     │
└──────────────────────────────────────┘
```

# 10. Live Activity 기술 규칙

## 10.1 자동 갱신되는 것 (업데이트 호출 불필요)

- `Text(timerInterval:countsDown:)` — 남은 시간
- `ProgressView(timerInterval:)` — 진행 바
- `context.isStale` — `staleDate` 도달 시 완료 뷰로 자동 전환

## 10.2 갱신 불가능한 것

- 앱이 백그라운드/종료 상태일 때의 임의 상태 변경 (푸시 없이는 불가)
- 초 단위로 올라가는 광석 카운터
- 연속 반복 애니메이션 (`repeatForever` 미지원)
- 세션 중 이벤트 표시 → §6에서 설계로 회피

## 10.3 ContentState

```swift
struct DeepMineActivityAttributes: ActivityAttributes {
    struct ContentState: Codable, Hashable {
        var phase: SessionPhase
        var expectedReward: Int
        var depth: Int
        var streakDays: Int
        var planID: String       // 스프라이트 ID만 전달
        var themeID: String
    }
    let sessionID: UUID
    let startedAt: Date
    let endsAt: Date
}
```

- 전체 4KB 이내. **이미지는 위젯 번들에 내장**하고 ID만 넘긴다
- `staleDate = endsAt`
- 활성 8시간 / 종료 후 잠금화면 4시간 (총 12시간) — 50분 세션에는 여유

## 10.4 App Intents

| Intent | 프로토콜 | 실행 위치 |
|---|---|---|
| `StartSessionIntent` | `LiveActivityIntent` | 앱 프로세스 |
| `AbandonSessionIntent` | `LiveActivityIntent` | 앱 프로세스 |
| `AcceptUpgradeIntent` | `AppIntent` | 위젯 프로세스 (App Group 공유 저장소) |
| `OpenGameIntent` | `AppIntent` (`openAppWhenRun`) | 앱 |

**주의**: Live Activity 시작은 원칙적으로 앱이 포그라운드여야 한다. 사용자가 직접 탭한 `LiveActivityIntent` / 단축어 / Siri 실행은 예외로 허용되지만, **기존 LA가 살아 있는 상태에서 새 LA를 요청하면 실패하는 사례가 보고**되어 있다. 반드시 `end(dismissalPolicy:) → request()` 순서로 구현하고, Phase 0에서 실기기 검증한다.

## 10.5 AlarmKit

- 세션 종료 알람을 `AlarmManager`로 스케줄 → **무음 모드와 집중 모드를 관통**
- `NSAlarmKitUsageDescription` 필수, 사용자 권한 동의 필요
- 자체 ActivityKit LA와 **동시 운용 시 Dynamic Island 경합 가능성** → Phase 0 검증 항목
- 검증 실패 시 대안: 진행 표시를 AlarmKit의 카운트다운 LA로 통합하고 커스텀 아트를 축소

# 19. 성공 기준

## 19.1 주요 지표

| 지표 | 목표 |
|---|---|
| 세션 완료율 (중도 이탈 반대) | 80% 이상 |
| D7 리텐션 | 25% 이상 |
| 주간 1인 누적 집중 시간 | 200분 이상 |
| 차단 기능 활성화율 | 60% 이상 |
| 첫 프레스티지 도달률 (14일) | 30% 이상 |

## 19.2 폐기한 지표

"세션 완료 후 5분 이내 재시작 비율" — 과사용을 유도하는 지표라 채택하지 않는다.

## 19.3 반증 조건

다음 중 하나면 컨셉을 재검토한다.

- 차단 기능 활성화율이 30% 미만 → 차단이 진입 장벽으로 작동 중
- 세션 완료율이 60% 미만 → 심층 갱도 리스크 설계 실패
- DI/StandBy 경유 재시작이 전체 시작의 10% 미만 → 표시 계층 투자 대비 효용 없음
