# 0. 2026-08-02 current implementation amendment

이 절은 2026-08-02 현재 코드, `DECISIONS.md` D-067~D-079, `PROJECT_STATUS.md`와
`BUILD_REPORT.md`의 검증 사실을 스펙에 반영한다. 아래 옛 절과 충돌하면 이 amendment가

## 0.1 현재 제품·경제 계약

- DeepMine은 **방치형 세로 갱도 클리커**다. 실제 암반 탭, 광차 자동 굴착과 8시간 오프라인
  생산만으로 정련과 프레스티지까지 도달할 수 있어야 한다.
- 집중 출정은 선택 기능이다. 세션 복구, 시작 버튼의 비동기 준비, 활성 세션 동안 홈 타이머와
  오프라인 정산을 모두 멈춰 같은 벽시계 시간을 두 번 지급하지 않는다.
- 현재 집중 완료는 별도 보상 경제다. 실제 `MiningLoop` 출력 배율과 완전히 통합된 것으로
  간주하지 않으며, 이 통합은 열린 제품 과제다.
- 옛 Lv.200 제품 상한은 제거됐지만 Lv.100,000 산술 안전 천장은 남으며 심도 1,499,925m에서
  도달한다. 드릴·광차·램프는 그 전까지 6레벨마다 다음 정련을 열고 정련 비용은 광석이다.
  드릴·광차는 해당 출력 ×2.5, 램프는 기본 치명타 배율에 ×√2.5 계수를 적용한다. 램프 화면은
  레벨·영구 강화 가산값을 포함한 실제 전후 총 치명타 배율을 표시한다.
- 지갑, 암반 내구·보상, 데미지, 장비·정련 가격, 구매 결과와 주요 추천 비용의 진실 타입은
  `BigNumber`다. 시간·확률·화면 좌표는 유한 계약이므로 `Double`을 유지한다.
- 자동화가 없을 때 추천은 첫 광차 Lv.2, ◆180을 절대 저축 목표로 유지한다. 더 싼 장비가
  구매 가능해도 이 기능 해금 추천을 바꾸지 않으며 충분히 모이기 전 버튼은 비활성이다.
- 홈은 현재 암반 보상, 남은 탭/자동 ETA, 자동 광석/초·층/초, 구매·정련 전후 출력과
  증가율을 Core 계산에서 표시한다.
- 프레스티지는 현재 위치·장비·장비 분기·정련을 초기화하고 최고 심도와 기억 장비를 보존한다.
  정련 MAX와 기억 정련 일괄 재설치는 아직 없다.

## 0.2 정산·저장·콘텐츠 계약

- 장시간 정산은 첫 512세그먼트 뒤 최대 11개의 6,144세그먼트 carry pass를 쓴다. 한 호출의
  최대 순회는 68,096세그먼트다. 150km·500km의 8시간×75% 회귀는 잔여 없이 끝나며,
  그보다 큰 병적 입력은 종료 보장을 위해 `wasTruncated`와 `unspentDamage`를 남긴다.
- SwiftData의 일반 저장, 원자적 명령 적용, 세션 종료 커밋은 같은 전체 상태 매핑을 쓴다.
  현재/기억 장비, 정련 단계와 달성 업적을 모두 보존한다. 레거시 빈 필드는 현재 장비,
  정련 없음, 업적 없음으로 안전하게 읽는다.
- 경제 지역은 지표/수정/폐허/심연이다. 5km pressure, 20km fault, 100km core는 심연 내부의
  시각 지질 세대이며 보상·지역 ID를 새로 만들지 않는다.
- 장기 진행 에셋 7종은 versioned v2 PNG, raw/processed 원본, manifest와 provenance를
  보존한다. CI는 정확한 7개 ID, PNG CRC/zlib, 크기, 네 안료, 알파, SHA, 카탈로그/웹 복사와
  provenance 원본 경로를 검사한다.

## 0.3 웹·배포·검증 경계

- 웹은 Swift Core의 상수·공식·첫 광차 저축·램프 정련식을 대조하는 조기·중기 formula
  harness다. JavaScript `number` 범위를 iOS `BigNumber`와 동등하다고 보지 않는다.
- Pages PR은 build/module smoke/static artifact까지만 수행한다. artifact 업로드와 배포,
  `pages: write`/`id-token: write`는 main push의 deploy job만 가진다.
- 시뮬레이터 병합 증거와 실기기 출시 증거를 구분한다. Core/App 테스트와 generic build 성공은
  FamilyControls, AlarmKit, Live Activity, 실제 VoiceOver/Reduce Motion/햅틱을 증명하지 않는다.
- 2026-08-02 로컬 closeout은 Core 282/282, App 단위 150/150, 정련 XCUITest 1/1,
  웹 15/15, 에셋 7/7과 generic iOS device build 통과다. 원격 Actions/Pages는 push 전,
  시스템 표면은 실기기 전이므로 미검증이다.

## 0.4 아직 열린 제품 계약

1. 실제 홈 추천·저축·정련·MAX 정책을 그대로 실행하는 30/90/180일 시뮬레이션
2. 집중 완료를 별도 광석 지급이 아니라 실제 `MiningLoop` 가속으로 통합
3. 정련 MAX, 프레스티지 후 기억 정련 재설치와 손실/재구축 UX
4. `NextStepPlanner` 극후반 진행도의 `BigNumber` 전환과 호환용 `cost: Double` 제거 계획
5. 통계·도전과제의 세션 중심 잔여 비중과 첫 수정의 명확한 소비처
6. Lv.100,000 뒤에도 유한 연산·저장을 보존하는 true-uncapped 성장 계약
7. 전체 XCUITest, 원격 Pages/Actions, 실기기 시스템 표면 릴리스 게이트

# 1. 제품 정의

> **개정 (2026-07-31, D-033/D-037/D-038; 2026-08-02 amendment)**: 이 절은 피벗으로 재작성됐다. 이전 판은
> 집중을 유일한 성장 입력으로 규정했고, 그 문장이 게임 전체를 세션에 묶었다. 현재
> 제품은 아이들 클리커이며 집중은 선택적 증폭기다. 피벗 이전 판은
> `pomodoro-v1-focus-blocking` 브랜치와 `pre-pivot-v1` 태그에 보존돼 있다.

## 1.1 한 줄 정의

**DeepMine은 암반을 부수며 광산을 아래로 넓혀가는 채굴 게임이고, 원하면 방해 앱을 실제로
차단해 생산을 증폭할 수 있다.**

## 1.2 정체성 선언

- 이건 **아이들 클리커**다. 앱을 닫아도 기계가 계속 캔다.
- 성장 입력은 둘이다. **자동 생산이 기본**이고 **집중은 선택적 증폭기**다.
- Screen Time 권한을 주지 않아도 게임은 완결된다. 권한은 더 좋게 만들 뿐 필수가 아니다.
- 방해 앱을 실제로 차단할 수 있는 아이들 게임은 없다. 이것이 유일한 차별점이며,
  토대가 아니라 기능으로 유지한다.
- 숫자를 굴리는 대상은 **부순 암반과 그 위에 쌓은 기계**다.

## 1.3 핵심 루프

```text
암반을 탭해 데미지
→ 세그먼트 파괴, 광석 획득
→ 장비 구매로 자동 데미지 증가
→ 앱을 닫아도 광석 누적 (오프라인)
→ 심도 관문을 넘어 새 지층
→ 불안정한 핵에서 붕괴(프레스티지)
→ 영구 연구로 더 빠르게 재시작
```

선택적 증폭 루프:

```text
깊은 집중 시작 (선택)
→ 방해 앱 차단, Live Activity에 진행 표시
→ 홈 채굴과 겹치지 않는 집중 보상 계산
→ AlarmKit 알람으로 종료
→ 검증 등급에 따른 수확 수령
```

증폭 루프를 한 번도 쓰지 않아도 위의 핵심 루프만으로 게임이 성립해야 한다. 이것이
증폭기 설계의 판정 기준이다.

# 2. 집중 검증 — 차단 기반

## 2.1 원칙

감지가 아니라 **차단**한다. 감시당하는 느낌 대신 "갱도에 들어가면 문이 닫힌다"는 규칙감을 준다.

## 2.2 구현

- `FamilyControls`로 사용자가 방해 앱/카테고리를 직접 선택 (`FamilyActivityPicker`)
- 세션 시작 시 `ManagedSettingsStore`로 shield 적용
- 세션 종료 또는 중도 포기 시 shield 해제
- `DeviceActivityMonitor` 익스텐션의 `intervalDidStart` / `intervalDidEnd`로 세션 경계 보강

> **entitlement**: `com.apple.developer.family-controls` (Individual). Apple에 별도 신청 필요, 승인까지 수 주. **프로젝트 착수와 동시에 신청**한다. 크리티컬 패스.

## 2.3 세 단계 검증 등급

| 등급 | 조건 | 보상 |
|---|---|---|
| 봉인 채굴 | 차단 목록 활성 + shield 유지 | ×1.00 (기준) |
| 개방 채굴 | 차단 미설정 / 권한 거부 | ×0.75, "검증 배지" 미획득 |
| 붕괴 | 세션 중 shield 강제 해제 | 심층 갱도면 보상 0, 그 외 50% |

폴백을 벌이 아니라 **등급**으로 표현해서, entitlement 미승인 상태에서도 제품이 출시 가능하도록 한다.

## 2.4 시간 조작 방어

- `Date()`와 `mach_continuous_time()` 기반 경과시간을 **동시 기록·교차 검증**
- 두 값의 차이가 임계 초과 시 해당 세션은 개방 채굴 등급으로 강등
- 기기 재부팅으로 단조 시계가 리셋되는 경우는 정상 처리(강등 없음, 대신 벽시계 기준 채택)

# 3. 세션과 채굴 계획

## 3.1 세션 길이

| 세션 | 길이 보정 |
|---|---:|
| 15분 | ×1.00 |
| 25분 | ×1.10 |
| 50분 | ×1.30 |

v0.1의 10분을 15분으로 올린다. 10분은 차단 세팅 비용 대비 보상이 낮다.

## 3.2 채굴 계획 (신규 · 핵심 차별화)

시작 버튼을 **시간 선택이 아니라 전략 선택**으로 만든다.

| 계획 | 보상 | 광맥 확률 | 중도 이탈 시 |
|---|---:|---:|---|
| 안전 갱도 | ×1.0 | 기본 | 경과분 50% 지급 |
| 심층 갱도 | ×1.6 | 기본 | **전액 소실 + 스트릭 유지 실패** |
| 탐사 갱도 | ×0.8 | ×3.0 | 경과분 50% 지급 |

- 심층 갱도는 최초 3세션 완료 후 해금 (첫 사용자를 태우지 않는다)
- 계획 선택은 1탭, 기본값은 직전 선택 유지

## 3.3 세션 상태

```swift
enum SessionPhase: String, Codable {
    case preparing
    case mining
    case completed
    case abandoned
}

enum MinePlan: String, Codable {
    case safe, deep, survey
}
```

`rareFound`는 삭제한다. 사유는 §6.

# 4. 경제 시스템

## 4.1 자원

| 자원 | 역할 |
|---|---|
| 광석 | 일반 업그레이드 |
| 수정 | 희귀 업그레이드, 테마 해금 |
| 핵 조각 | 프레스티지 영구 성장 |

## 4.2 보상식 (세션 카운트 기반)

```text
세션 보상 =
    기본채굴량
  × 성장계수 ^ min(누적 집중 크레딧, 20)
  × 세션길이보정
  × 채굴계획배율
  × 검증등급배율
  × 일일스트릭배율
  × 장비배율
  × 광맥배율
  × 피로도계수
```

- `기본채굴량` = 100
- `성장계수` = **1.04** (튜닝 범위 1.03~1.05)
- 세션 20회 지점에서 체감 약 2.2배가 나오면 적정
- 구현 보정(2026-07-29): 집중 크레딧은 `완료 집중분 ÷ 25`이며 성장 지수는 20에서 상한을 둔다. 30일 시뮬레이션에서 무제한 누적 지수가 경제를 폭발시킨 결과를 반영했다. 프레스티지 후에도 lifetime 기준 상한 배율은 유지된다.

## 4.3 일일 소프트캡 (광맥 피로도)

| 당일 누적 집중 | 피로도계수 |
|---|---:|
| 0~240분 | ×1.00 |
| 240~360분 | ×0.50 |
| 360분 초과 | ×0.25 |

- UI에서는 **"광맥이 지쳤습니다 · 자정에 회복"**으로 표현
- 패널티 문구를 쓰지 않는다. 과사용 유도 제품이 되지 않기 위한 장치이자, 인플레 통제 수단

## 4.4 장비 가격

```text
가격 = 장비별 기본가격 × 1.34^(현재레벨-1)
```

| 레벨 | 드릴 가격 |
|---:|---:|
| 1 → 2 | 100 |
| 2 → 3 | 134 |
| 3 → 4 | 180 |
| 4 → 5 | 241 |
| 5 → 6 | 323 |

기억된 최고 레벨 미만을 다시 구매할 때는 위 가격의 50%를 적용한다. 옛 Lv.200 제품 상한은
없지만 Lv.100,000 산술 안전 천장은 남으며 정련 해금은 §5.3을 따른다.

## 4.5 심도

심도는 **부순 암반의 함수**다 (D-040).

```text
심도(m) = 현재 세그먼트 위치 × 4 + 남은 마이그레이션 보정(0~3m)
```

집중 세션은 심도를 주지 않는다. 광석을 주고, 그 광석이 장비가 되어 암반을 더 빨리 부술
뿐이다. Screen Time 권한이 없어도 심도가 오르는 것이 이 규칙의 목적이다.

심연 광맥은 미개척 세그먼트를 건너뛰지 않는다. 건너뛴 암반의 광석을 영구히 잃는 역전이
있었으므로 현재 보상은 수정 4개다. 옛 `bonusDepth` 필드는 저장 호환 정규화에만 남는다.

- **현재 심도**: 지금 서 있는 위치. 프레스티지로 0이 된다
- **최고 심도**: 도달했던 가장 깊은 곳. 프레스티지가 되돌리지 않는다 (D-046)

심도 증가로 해금되는 것: 광산 테마, 광맥 종류와 지역. 전부 **최고 심도**를 기준으로
판정하므로 프레스티지가 이미 연 문을 닫지 않는다. 장비는 Lv.100,000 산술 안전 천장까지 열린다.

지역 관문: 수정층 240m, 폐허 800m, 심연 1,600m (D-044).

장비 가격·출력·정련 계산은 `BigNumber` 범위를 보존한다. Lv.100,000 전에는 6레벨마다 열린
정련이 내구 성장률을 따라가는 두 번째 곱연산 축이며, 천장 이후는 아직 열린 제품 계약이다.

## 4.6 연속 갱도 표현

- 4m는 내구·보상 계산 단위이지 화면 타일이 아니다.
- 화면은 `pointsPerMeter = 9`의 연속 심도 좌표를 쓰고, 굴착 헤드는 현재 세그먼트의
  `brokenFraction × 4m`만큼 실제로 내려간다.
- 24m보다 얕은 구간은 부족한 위쪽 깊이를 열린 지표 갱도 여백으로 보충해 굴착 헤드가
  상단에 잘리지 않게 한다. 지층 자체의 최소 심도는 계속 0m다.
- 위쪽 24m에는 지나온 통로와 균열·레일·광차·램프가 남고, 아래쪽은 램프가 비추는
  8~36m만 보인다.
- 지층 덩어리는 지역 경계(240/800/1600m)에서만 나뉜다. 4m마다 사각 암반을 반복하지 않는다.
- 심도 눈금은 장면 위 오버레이이며 레이아웃 폭을 점유하지 않는다.
- 이전 구간의 통로 폭은 그 구간을 뚫을 때의 드릴 상태를 보존한다.
- 열린 통로의 끝과 현재 암반 사이에 별도 수평 경계나 떠 있는 작업대를 두지 않는다. 통로
  목의 파쇄 립, 아래로 자라는 절삭 홈, 세로 균열은 같은 중심 접점에서 최소 1px 이상 겹친다.
- 수동 탭과 자동 굴착은 같은 준비→전신 하강→접촉→반동 타임라인을 쓴다. 캐릭터의 몸이
  멈춘 채 도구만 움직이거나, 데미지가 접촉 프레임과 별도 주기로 적용되는 표현을 금지한다.

## 4.7 첫 뷰포트 경제 폐루프

- 개별 탭에 광석을 새로 지급하지 않는다. 광석 보상은 기존처럼 4m 암반 파쇄 시 확정한다.
- 현재 작업 접점에는 남은 파쇄율과 해당 암반의 예상 광석을 함께 표시한다.
- 첫 뷰포트 하단 행동대에는 `현재 암반 예상 광석`, 자동 굴착 기준 완료 ETA,
  구매 가능한 추천 장비 1개와 그 효과·비용을 노출한다.
- 추천은 자동 구매하지 않으며 플레이어가 명시적으로 버튼을 눌러야 한다. 구매 뒤 광석,
  장비 레벨, 장면 효과, 다음 추천과 접근성 상태 알림이 한 상태 갱신으로 바뀐다.
- 행동대는 화면 전체 탭 가속에서 제외하되, 나머지 비버튼 영역의 탭 계약은 유지한다.
- 390×844에서 갱도와 행동대가 첫 화면 안에 들어오고 가로 스크롤이 없어야 한다.

## 4.8 공명 결절 사건

- 공명 결절은 포그라운드 홈 갱도의 간헐 직접 조작 사건이다. 집중 출정, Live Activity,
  백그라운드 정산에는 등장하지 않으며 §6의 종료 시 광맥 판정과 별도다.
- 이번 페이지 세션의 첫 발견은 기능을 학습할 수 있도록 약 5초 뒤 한 번 노출한다. 이후에는
  화면이 보이는 동안만 2~5분의 무작위 간격으로 등장한다.
- 결절은 12초 동안 실제 버튼으로 남는다. 자동 굴착은 수령하지 않으며 플레이어가 명시적으로
  눌러야 한다. 수령하지 못하면 광석이나 배율을 지급하지 않고 `신호 소실` 상태를 알린다.
- 수령하면 18초 동안 수동 탭과 자동 굴착 출력이 모두 ×2가 된다. 접촉 타임라인과 4m 파쇄
  보상 경제는 그대로 유지하며, 종료 시 원래 출력으로 복귀한다.
- 활성 결절, 회수/놓침, 과충전 남은 시간은 색만이 아니라 텍스트와 접근성 상태로 구분한다.
  결절은 44px 이상의 터치 영역과 고정 접근성 이름을 갖는다.
- 화면이 숨겨지면 아직 수령하지 않은 활성 결절은 놓침으로 계산하지 않고 추적을 일시정지한다.
  Reduce Motion에서는 회전·호흡·이동을 없애되 등장·남은 시간·배율 상태는 유지한다.

## 4.9 웹 타격 리듬과 접촉 피드백

- 수동·자동 타격은 `quick 560/202ms`, `heavy 690/249ms`, `critical 760/274ms`의
  `전체 동작 시간/접촉 시점` 계약을 사용한다. 전신 스프라이트, 막장 반동, 섬광, 세로 균열,
  파편, 데미지와 소리는 각 변주의 같은 접촉 시점에 묶는다.
- 자동 굴착은 세 번째 가시 타격마다 강타를 사용한다. 수동 타격도 일반 타격 사이에 강타를
  섞고, 기존 급소 확률에 따른 결정적 타격은 별도 크리티컬 전신 포즈와 강화된 파편으로 표시한다.
- 수동 타격 중에는 자동 액터가 포즈를 덮어쓰지 않는다. 겹친 주기의 자동 데미지는 보류했다가
  다음 가시 접촉 프레임에 합산하며 빠뜨리지 않는다. 클릭은 방치 생산을 대체하거나 손해 보게
  하지 않고 순수 가속으로 남고, 붕괴가 접촉 프레임 밖에서 시작되지 않는다.
- 웹 SFX는 새 의존성이나 외부 파일 없이 짧은 square-wave 접촉음과 붕괴음으로 합성한다.
  브라우저 정책상 첫 사용자 제스처 전에는 무음이며, 그 뒤 자동 타격에도 적용한다. 독립 44px
  SFX 토글은 화면 전체 채굴 입력에서 제외한다.
- Reduce Motion에서는 각 타격을 160ms, 접촉을 80ms로 줄이되 접촉 프레임과 데미지의
  동기화는 보존한다. iOS의 저작 8-bit 자산과 `GameFeedbackEvent.systemSoundID` 교체는
  이 웹 프로토타입과 별도 릴리스 작업이다.

## 4.10 장비 구매의 물리적 누적 증거

- 장비 구매는 숫자와 티어 이미지 교체로 끝내지 않는다. 첫 뷰포트의 열린 통로에 작업조,
  운행 광차, 광차 적재량, 벽면 작업등이 실제 개수로 늘어나 자동 생산 기반이 축적돼야 한다.
- 작업조는 장비 총 레벨이 시작값 11을 넘을 때마다 1명씩 늘어 1~4명으로 보인다. 광차는
  레벨 2부터 1~4대, 적재는 1~3칸, 작업등은 램프 레벨과 장거리 반사경을 합쳐 1~5기로 보인다.
- 드릴·광차·램프 강화와 레벨 5 분기 설치는 해당 설비만 짧게 점등하고, `설비 증설 완료`,
  장비 레벨, 늘어난 물리적 결과를 같은 접근성 상태 알림으로 제공한다.
- 구매는 §4.7처럼 명시적 버튼에서만 일어나며 자동 구매를 추가하지 않는다. 화면 전체 탭,
  자동 굴착, 4m 파쇄 보상과 접촉 타임라인도 바꾸지 않는다.
- 1280×720과 390×844의 첫 화면에서 설치 알림이 하단 행동대를 가리지 않고 가로 스크롤이
  없어야 한다. Reduce Motion에서는 이동·점등을 제거하고 늘어난 설비의 정적 최종 배치를 남긴다.

## 4.11 면 단위 타격과 구조적 내실 단계

- 곡괭이 접촉 섬광만 커지는 것으로 전신 공격을 표현하지 않는다. 준비 자세에서 몸통·무릎·
  양손이 함께 내려오고, 접촉 순간 충격파·좌우 분기 균열·분진이 암반 폭의 76% 이상으로 번진다.
  강타는 84%, 급소 타격은 92%까지 넓어져 힘의 차이가 면적으로 읽혀야 한다.
- 주 광부는 작업면의 부속 픽셀이 아니라 전신 실루엣으로 읽혀야 한다. 웹 1280×720 기준
  152px 프레임을 사용하고 예비동작과 접촉 사이에 20px 이상의 전신 수직 변위를 둔다.
- 내실 단계는 작은 스프라이트 수만 늘리지 않는다. 작업조 1명마다 통로 전체를 가로지르는
  작업 데크·지지 기둥·보급 상자가 한 층씩 설치되고, 광차 3대부터 레일이 28px 단선에서
  66px 복선으로 확장된다. 램프는 28px 설치물과 통로 안쪽을 향하는 광원 구역을 함께 만든다.
- 첫 화면에는 `갱도 내실 N단계`와 작업조·광차·조명 수를 보조 판독으로 제공하되, 숫자보다
  데크 층수·레일 폭·운송 대열·광원 구역의 구조 변화가 먼저 보여야 한다.
- 자동 굴착도 같은 면 단위 충격을 사용하되 새 경제 상태나 데미지를 추가하지 않는다.
  Reduce Motion에서는 넓은 이동 충격파를 제거하고 전신 최종 포즈·세로 균열·설비 구조를 남긴다.

## 5.1 추천 강화

자동 실행하지 않는다. 장비 화면과 귀환 handoff에 **추천 1개 + 수락 버튼**만 노출한다.
자동 생산이 0인 동안에는 일반 효율식보다 첫 광차 Lv.2 ◆180 저축 목표가 우선한다.

```text
효율 = 생산 증가량 ÷ 업그레이드 비용
동률이면 드릴 우선
```

```text
[추천: 드릴 → LV.9  1,400]   [앱에서 고르기]
```

## 5.2 장비 분기

레벨 5부터 각 장비는 이번 하강에서 한 갈래만 설치한다. 프레스티지는 선택을 초기화해 다음
하강에서 다른 조합을 시험할 수 있게 한다.

| 장비 | 선택 A | 선택 B |
|---|---|---|
| 드릴 | 확폭 비트: 통로 폭 +20pt | 충격 비트: 탭 데미지 ×1.35 |
| 광차 | 쌍선 레일: 자동 데미지 ×1.25, 광차 +1 | 대형 호퍼: 파괴 광석 ×1.25 |
| 램프 | 장거리 반사경: 아래 시야 +8m | 광맥 렌즈: 치명타 확률 +8%p |

분기 가격은 드릴 460, 광차 560, 램프 660 광석이다. 같은 장비의 두 선택을 동시에 장착할 수
없으며, 선택 결과는 수치와 갱도 장면 양쪽에서 확인돼야 한다.

## 5.3 정련

- 각 장비는 Lv.7에서 R1을 처음 구매할 수 있고 이후 6레벨마다 다음 등급이 열린다.
- 정련은 광석으로 구매한다. 드릴·광차는 해당 출력 ×2.5, 램프는 기본 치명타 배율에
  ×√2.5 계수를 적용한다.
- 패널은 다음 등급, 필요 레벨과 비용을 항상 보여 주며 잠긴 행의 배율은 실제 최소 해금 레벨
  상태로 preview한다. 성공 알림은 실제 저장 전후 출력·ETA와 증가율을 표시한다.
- 프레스티지는 현재 정련을 초기화한다. 기억 정련 MAX 재설치는 §0.4의 열린 과제다.

# 6. 희귀 광맥 — 종료 시 공개

## 6.1 왜 세션 중에 표시하지 않는가

앱이 백그라운드에서 suspend되면 Live Activity를 갱신할 수 없다. 세션 중간에 "✨발견"으로 Dynamic Island를 바꾸려면 (a) 푸시 서버 또는 (b) 사용자를 방해하는 알림이 필요하다. 둘 다 제품 원칙에 어긋난다.

따라서 **광맥 판정은 세션 종료 시점에 일괄 수행하고 결과도 그때 공개**한다. 세션 중에는 어떤 이벤트도 발생하지 않는다. 이것은 제약을 수용한 결과가 아니라, "집중을 절대 방해하지 않는다"는 원칙의 직접 구현이다.

## 6.2 종류

| 광맥 | 효과 |
|---|---|
| 푸른 광맥 | 세션 보상 ×1.5 |
| 수정 광맥 | 수정 획득 |
| 고대 금고 | 테마 또는 장식 해금 |
| 공명층 | 다음 세션 보상 ×2 |
| 심연 균열 | 심도 추가 증가 |

## 6.3 연출

종료 시 `staleDate` 전환으로 잠금화면·DI가 완료 상태로 바뀌고, 광맥이 있으면 그 상태에 함께 표시된다. 상세 연출은 앱 진입 시.

| 3 | ×1.10 |
| 7 | ×1.25 |
| 14 | ×1.40 |
| 30 | ×1.60 |

## 7.2 유예

- 주 1회 "휴광일" 자동 소모 → 하루 놓쳐도 스트릭 유지
- 유예 소진 후 실패 시 연속 일수는 **0이 아니라 절반**으로 감소

현실 일정과 싸우지 않는다. 스트릭이 벌칙이 되면 이탈한다.

## 7.3 세션 내 배율

세션 단위 콤보(10분 내 재시작)는 **폐기**한다. 대신 당일 N번째 세션에 소폭 보너스만 준다.

| 당일 N번째 | 보정 |
|---:|---:|
| 1 | ×1.00 |
| 2 | ×1.05 |
| 3+ | ×1.10 |

# 8. 프레스티지

```text
이번 하강에서 부순 암반 목표 도달
→ 광석·장비·위치 초기화 (최고 심도와 해금은 유지)
→ 핵 조각 획득
→ 영구 보너스
```

- 1회차 목표: **부순 암반 120층** (일반 사용자 기준 2~3일)
- 이후 회차는 필요 층 수 ×1.5씩 증가
- 핵 조각: `floor(부순 층 ÷ 40)`, 최소 1
- 위치는 지표로 돌아간다. 장비만 초기화하고 위치를 유지하면 리셋 직후 깰 수 없는 암반
  앞에 서게 되기 때문이다 (D-046)
- 핵 조각 투자처 3종: 굴착 기억(기본 채굴량) / 공명 탐지(광맥 확률) / 압축 시간(긴 세션 보정)

# 10. Live Activity 기술 규칙

## 10.1 자동 갱신되는 것 (업데이트 호출 불필요)

- `Text(timerInterval:countsDown:)` — 남은 시간
- `ProgressView(timerInterval:)` — 진행 바
- `context.isStale` — `staleDate` 도달 시 완료 뷰로 자동 전환

## 10.2 갱신 불가능한 것

- 앱이 백그라운드/종료 상태일 때의 임의 상태 변경 (푸시 없이는 불가)
- 초 단위로 올라가는 광석 카운터
- 연속 반복 애니메이션 (`repeatForever` 미지원)
- 세션 중 이벤트 표시 → §6에서 설계로 회피

## 10.3 ContentState

```swift
struct DeepMineActivityAttributes: ActivityAttributes {
    struct ContentState: Codable, Hashable {
        var phase: SessionPhase
        var expectedReward: Int
        var depth: Int
        var streakDays: Int
        var planID: String       // 스프라이트 ID만 전달
        var themeID: String
    }
    let sessionID: UUID
    let startedAt: Date
    let endsAt: Date
}
```

- 전체 4KB 이내. **이미지는 위젯 번들에 내장**하고 ID만 넘긴다
- `staleDate = endsAt`
- 활성 8시간 / 종료 후 잠금화면 4시간 (총 12시간) — 50분 세션에는 여유

## 10.4 App Intents

| Intent | 프로토콜 | 실행 위치 |
|---|---|---|
| `StartSessionIntent` | `LiveActivityIntent` | 앱 프로세스 |
| `AbandonSessionIntent` | `LiveActivityIntent` | 앱 프로세스 |
| `AcceptUpgradeIntent` | `AppIntent` | 위젯 프로세스 (App Group 공유 저장소) |
| `OpenGameIntent` | `AppIntent` (`openAppWhenRun`) | 앱 |

**주의**: Live Activity 시작은 원칙적으로 앱이 포그라운드여야 한다. 사용자가 직접 탭한 `LiveActivityIntent` / 단축어 / Siri 실행은 예외로 허용되지만, **기존 LA가 살아 있는 상태에서 새 LA를 요청하면 실패하는 사례가 보고**되어 있다. 반드시 `end(dismissalPolicy:) → request()` 순서로 구현하고, Phase 0에서 실기기 검증한다.

## 10.5 AlarmKit

- 세션 종료 알람을 `AlarmManager`로 스케줄 → **무음 모드와 집중 모드를 관통**
- `NSAlarmKitUsageDescription` 필수, 사용자 권한 동의 필요
- 자체 ActivityKit LA와 **동시 운용 시 Dynamic Island 경합 가능성** → Phase 0 검증 항목
- 검증 실패 시 대안: 진행 표시를 AlarmKit의 카운트다운 LA로 통합하고 커스텀 아트를 축소

# 19. 성공 기준

## 19.1 주요 지표

| 지표 | 목표 |
|---|---|
| 세션 완료율 (중도 이탈 반대) | 80% 이상 |
| D7 리텐션 | 25% 이상 |
| 주간 1인 누적 집중 시간 | 200분 이상 |
| 차단 기능 활성화율 | 60% 이상 |
| 첫 프레스티지 도달률 (14일) | 30% 이상 |

## 19.2 폐기한 지표

"세션 완료 후 5분 이내 재시작 비율" — 과사용을 유도하는 지표라 채택하지 않는다.

## 19.3 반증 조건

다음 중 하나면 컨셉을 재검토한다.

- 차단 기능 활성화율이 30% 미만 → 차단이 진입 장벽으로 작동 중
- 세션 완료율이 60% 미만 → 심층 갱도 리스크 설계 실패
- 집중 LA 경유 앱 복귀가 전체 집중 출정의 10% 미만 → 표시 계층 투자 대비 효용 없음

## 열린 질문

1. 심층 갱도의 전액 소실이 실제로 동기가 되는가, 아니면 회피 대상이 되는가
2. 하루 목표 시간을 사용자가 직접 정하는 것이 좋은가, 시스템이 제안하는 것이 좋은가
3. 한국 시장 우선인가 글로벌 우선인가 — 결제 저항과 ASO 전략이 갈린다
4. 수정의 명확한 소비처를 외형/장식으로 둘 것인가, 통화를 단순화할 것인가
5. 집중 보상을 어떤 `MiningLoop` 배율·지속시간으로 통합할 것인가
6. Lv.100,000 산술 천장을 제거하면서 정수 순회·저장·UI 성능을 어떻게 유한하게 보장할 것인가
