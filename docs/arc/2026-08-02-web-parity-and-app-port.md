# 웹·앱 경제 통일과 웹 기준 전량 포팅 (2026-08-02)

이 문서는 한 세션의 작업 기록이다. 결정의 근거는 `docs/DECISIONS.md` D-061~D-065에,
검증 결과는 `BUILD_REPORT.md`에 있다. 여기에는 **무엇을 왜 바꿨고 무엇이 남았는지**를
한 곳에 모은다.

## 1. 출발점: 코드 전면 분석

문서가 아니라 코드와 실행 결과로 현재 상태를 확인하는 데서 시작했다. 문서는 대체로
정확했지만 세 가지가 사실과 달랐다.

| 확인한 것 | 결과 |
|---|---|
| `swift test --package-path DeepMineCore` | 195/195 — 문서와 일치 |
| `xcodebuild ... -destination 'generic/platform=iOS' build` | **실패**. `CODE_SIGNING_ALLOWED=NO` 필요 |
| 전체 `DeepMineAppTests` | 문서는 "미검증(환경 문제)". 실제로는 **133 통과 / 1 실패** |
| 웹 계약 테스트 8/8 | 전부 소스 문자열 grep. 동작을 검증하지 않는다 |
| Core 금지 import, `fatalError`, `try!` | 위반 0 |

### 발견 1 — 환경 문제로 분류된 구간이 진짜 실패를 가리고 있었다

`DesignSystemContractTests.testEquipmentArtTierBoundariesClampToShippedRange`가 피벗
이전의 장비 아트 티어 경계(20/40/60)를 기대하고 있었다. `EquipmentEngine.visualTier`는
클리커 피벗에서 4/14로 옮겼으므로 이 테스트는 그때부터 계속 실패했다.

`PROJECT_STATUS.md`가 전체 스위트를 "`Mach error -308`, runner 연결 전 종료"로 기록해
두었기 때문에 아무도 이 실패를 보지 못했다. 스위트는 정상적으로 완주한다.

### 발견 2 — 웹과 앱이 서로 다른 게임이었다

| 항목 | Core | 웹 (당시) |
|---|---|---|
| 암반 내구 | `10 × 1.058^세그먼트` | `104 × 1.018^층` |
| 탭 데미지 | `1.0 × 1.12^(lv-1)` | `12 × 1.16^(lv-1)` |
| 자동화 | `0.5 × lv × 1.12^lv` | `5 × 1.22^(lv-2)` |
| 강화 비용 지수 | 1.34 | 1.31 |
| 크리티컬 | 0.05 + 0.01/lv, 상한 0.6 | 0.08 + 0.025/lv, 상한 0.42 |
| 장비 티어 경계 | 4 / 14 | 5 / 9 |
| 초기 장비 | 1 / 1 / 1 | 4 / 5 / 2 |
| 층 광석 | `4 × 1.07^세그먼트` | `28 + 심도×0.12` |

여기에 앱 테스트가 기대하던 20/40까지 더하면 티어 경계만 세 가지였다. 결과적으로
D-056의 완료 ETA, 보상 리듬, 추천 강화 타이밍처럼 **웹에서 승인한 체감은 웹 수치 위에서만
성립**했고, 그대로 옮겨도 앱에서 재현되지 않는다.

### 발견 3 — 웹 계약 테스트는 동작을 보증하지 않는다

`prototype-contract.test.mjs`는 앱을 실행하지 않고 `.tsx`/`.css` 소스를 정규식으로
매칭한다. `assert.match(prototype, /queueStrike/)`는 그 이름이 파일에 있다는 뜻이지
타격이 데미지를 넣는다는 뜻이 아니다. 변수명만 바꿔도 깨지고, 로직을 망가뜨려도 통과한다.

## 2. 무엇을 바꿨나

### 경제의 진리를 Core로 통일 (D-061)

웹의 자체 밸런스를 전부 걷어내고 `web/app/coreBalance.ts` 한 파일에 Swift 상수를 옮겼다.
Core를 진리로 둔 이유는 그 곡선이 180일 시뮬레이션과 심도 역전 금지 게이트로 튜닝된
값이기 때문이다 (D-044).

두 가지가 따라왔다.

- **데미지를 실수로 다룬다.** Core는 탭 1.0, 첫 광차 0.56/초에서 시작한다. 기존 웹처럼
  정수로 반올림하면 초반 게임이 통째로 사라진다. 반올림은 표시에서만 한다.
- **웹 초기 광차만 2레벨.** Core에서 광차 1레벨의 자동화는 정확히 0이고, 클릭해야만
  움직이는 기준안은 보여 주려는 방치 장면을 보여 주지 못한다. 이 한 칸이 유일한 예외다.

`core-balance-parity.test.mjs`가 Swift 소스에서 상수 40개를 직접 파싱해 대조한다.
값 하나를 변조해 실제로 실패하는지 확인했다.

### 웹 기준 D-055~D-060 앱 포팅 (D-062, D-063, D-064)

세 단계 모두 **계산을 Core 순수 타입으로 먼저 옮기고** SwiftUI는 결과만 그리게 했다.
웹에서 승인된 것은 화면이지 계산이 아니다.

| 단계 | Core에 만든 것 | 앱에 연결한 것 |
|---|---|---|
| D-055 | — (에셋·뷰) | `ShaftFrontierLip`, `MinerMiningStrip` 카탈로그 편입, `GameArtStripView`, 단일 4프레임 액터 |
| D-056 | `WorkFaceForecast` | `WorkFaceForecastBar` — 예상 광석·자동 ETA·남은 탭 수 |
| D-057 | `ResonanceNodeState` / `ResonanceNodeEngine` | `ResonanceNodeView` — 12초 창, 18초 ×2 부스트 |
| D-058 | `StrikeTimeline` / `.Cadence` | 스윙 주기·수동 보호·변주 교대·접촉 반동 |
| D-059 | `MineInfrastructure` / `Engine` | 작업조 데크, 광차 대수, 작업등 |
| D-060 | (D-058 접촉 시점 재사용) | 암반 폭 76/84/92% 압축대·충격파·분기 균열 |

몇 가지 설계 판단을 남긴다.

- **공명 결절은 이름부터 분리했다.** 앱의 기존 `VeinKind.resonance`는 세션이 건네주는
  보상 광맥이다. 결절은 잡아야 하는 것이고 광맥은 받는 것이다.
- **부스트는 탭·자동 데미지만 2배로 한다.** 크리티컬 확률까지 두 배가 되면 더 빠른
  게임이 아니라 다른 게임으로 읽힌다.
- **광차는 레벨 1에서 0대다.** 첫 광차 구매가 방치가 시작되는 순간이라는 Core 규칙과
  화면이 같은 말을 하게 된다.
- **작업조는 데크 위에 선다.** 아무것도 없는 통로에 선 광부는 장면에 붙인 스프라이트로
  읽힌다.
- **에셋 보류 해제.** D-055는 "웹 체감 승인 전 앱 카탈로그 편입 금지"를 명시했다.
  사용자 포팅 지시로 해제하고, 프롬프트·SHA·네 안료 검증 계약은 그대로 유지했다.

## 3. 작업 중 나온 실제 결함 다섯 가지

1. **첫 암반을 끝까지 깰 수 없었다.** 온보딩 카드가 갱도 씬을 고정 오프셋 48로 그려서,
   0m에서 24m 지표 inset 아래에 있는 작업면이 카드 밖으로 밀렸다. 암반은 바닥에 잘린
   조각으로만 보이고 **카드 중심 — XCUITest가 실제로 탭하는 지점 — 은 빈 갱도**였다.
   20번을 탭해도 데미지가 0이었다. `TASKS.md`에 미완으로 남아 있던 "첫 암반을 실제로
   끝까지 탭해 보상까지" 항목이 이것이었다. 헤드를 따라가도록 고쳐 8/8이 됐다.
2. **자동 굴착 중 광부가 얼어붙었다.** 자동화가 0.25초 시뮬레이션 스텝마다 0.56초짜리
   스윙을 재시작해, 예비동작 프레임에 멈춘 채 암반만 깎였다. 데미지 스텝과 보이는 스윙을
   별도 시계로 분리했다.
3. **광차 구매 대부분이 갱도에서 보이지 않았다.** 앱 광차 수가 `visualTier` 기반이라
   레벨 5와 15에서만 늘었다. 그 사이의 모든 구매는 숫자만 바꿨다.
4. **커진 액터가 탭 표적을 가로챘다.** 92pt 광부가 지반 버튼 위를 덮었다. 광부에 떨어진
   탭은 플레이어가 암반을 노린 탭이므로 hit test에서 뺐다.
5. **간트리가 광부 머리를 가로질렀다.** 124pt 구조물을 44pt 상부 지지대로 줄였다.

이 가운데 1번과 3번은 이번 변경이 만든 것이 아니라 **이미 있던 결함**이다.

## 5. 검증할 수 없었던 것

- **면 단위 충격**은 접촉 후 72ms 창이라 정지 캡처로 잡히지 않았다. 빌드와 타임라인
  테스트로만 뒷받침된다. 스크린샷 증거는 없다.
- **공명 과충전 배지**도 같은 이유로 캡처를 놓쳤다. 부스트 자체는 심도 급증(0m→28m)으로
  확인했다.
- 실기기 햅틱, VoiceOver 초점, Reduce Motion 체감은 여전히 시뮬레이터가 증명할 수 없다.

## 6. 남은 일

1. **웹 설비 파생을 `coreBalance.ts`로** (D-065). `cartFleetSize` 등은 값이 Core와
   같지만 아직 프로토타입 안에 있다. 패리티 계약이 없으므로 밸런스에서 겪은 드리프트가
   같은 방식으로 다시 열릴 수 있다. 남은 항목 중 가장 값싸고 효과가 크다.
2. 8-bit SFX 실제 제작. 웹에는 합성 SFX가 있고 앱은 시스템 사운드 ID에 머문다.
3. `RockEngine` 512층 절단 시 잔여 데미지 재정산. `wasTruncated`는 Core 안에서만
   전파되고 앱은 읽지 않아, 절단분이 조용히 소실된다.
4. `Resources.ore: Double` → `BigNumber` 마이그레이션.
5. 180일 heavy/light 누적 광석 역전(0.406배)의 최초 시점 분해.
6. 실기기 게이트 6종 (GATE-001~006).
