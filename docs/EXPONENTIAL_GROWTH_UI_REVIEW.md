## 결론

DeepMine은 현재 **세로 갱도라는 강한 공간적 정체성, 견고한 채굴 코어, 실제 접촉 프레임과 연결된 타격 연출**을 갖췄다. 그러나 **쿠키클리커식 지수 성장의 핵심 재미가 실제 앱 플레이로 완전히 전달되지는 않는다.**

핵심 원인은 네 가지다.

1. 수학적 발산을 만드는 두 번째 곱연산 축인 **정련(Refinement)을 앱에서 구매할 UI가 없다.**
2. 지갑과 데미지는 `BigNumber`지만 장비·정련 비용과 일부 배수는 여전히 `Double`이라 장기 구간에서 오버플로가 발생할 수 있다.
3. 화면은 현재 값은 보여주지만 **구매 전후 속도 변화, 광석/초, 층/초, 다음 ×2.5 도약**을 충분히 보여주지 않는다.
4. 지역 아트는 1,600m, 장비 아트는 Lv.15에서 사실상 소진되므로 수십~수백 km 성장과 시각적 축적이 맞지 않는다.

현재 평가는 다음과 같다.

| 항목 | 평가 | 판단 |
|---|---:|---|
| 제품 정체성 | 8/10 | 세로 갱도와 공간적 누적은 강한 차별점 |
| 타격·파괴 피드백 | 8/10 | 전신 타격, 접촉, 균열, 붕괴가 잘 연결됨 |
| 초기 경제 폐루프 | 6/10 | 보상→추천 강화는 연결됐으나 첫 자동화 시점 점검 필요 |
| Core 지수 성장 | 8/10 | 정련 포함 시 완만하게 발산하는 곡선 성립 |
| 실제 앱 지수 성장 | 3/10 | 정련 UI·대량 구매·성장률 비교 부재 |
| 장기 시각 성장 | 3/10 | 1.6km 이후 지역, Lv.15 이후 장비 외형 정체 |

## 1. 잘된 부분

### 1.1 깊이를 숫자가 아니라 장소로 표현한다

갱도는 과거 통로, 현재 막장, 미래 암반을 하나의 연속 좌표계로 구성한다. 4m 세그먼트는 경제 단위일 뿐 화면 행이 아니며, 굴착 헤드와 지층이 실제 위치로 이동한다. 지나온 보어 폭과 레일·광차·램프도 갱도에 누적된다.

이 구조는 일반적인 숫자 중심 방치형 게임보다 강한 제품 정체성을 만든다. DeepMine의 장기 방향은 숫자 UI를 쿠키클리커처럼 복제하는 것이 아니라 **광산이 물리적으로 증축되는 공간형 방치 게임**이어야 한다.

### 1.2 첫 화면의 기본 폐루프가 성립한다

현재 홈은 광석 → 갱도 → 현재 암반 보상·남은 탭/자동 ETA → 추천 강화 → 진행 화면 → 접힌 집중 증폭기 순이다. 집중 세션이 홈의 정체성을 점유하지 않고, 현재 생산과 소비가 먼저 보인다.

`WorkFaceForecastBar`가 자동화가 없을 때 가짜 ETA 대신 남은 탭 수를 보여 주는 것도 적절하다.

### 1.3 타격 애니메이션 구조가 견고하다

광부·양손·곡괭이는 하나의 4프레임 액터이며 준비→예비동작→접촉→반동을 같은 타임라인으로 재생한다. 접촉 프레임과 데미지 시점이 일치하고, 자동화 스텝과 보이는 스윙의 시계도 분리돼 있다.

약점은 48×48pt 조작 영역을 갖고, 액터는 탭을 가로채지 않는다. quick/heavy/critical의 암반 면 반응도 서로 다르다.

### 1.4 공명 결절은 올바른 간헐 보상이다

공명 결절은 고정 보상이 아니라 현재 탭·자동 생산을 일정 시간 ×2로 만든다. 따라서 후반에도 의미가 사라지지 않는다. 이 구조는 유지하되, 활성 중 실제 광석/초와 파쇄 속도가 얼마나 뛰었는지를 화면에서 더 강하게 보여줘야 한다.

## 2. 지수 성장 곡선 분석

### 2.1 현재 주요 증가율

| 요소 | 증가율 |
|---|---:|
| 암반 광석 | 세그먼트당 ×1.07 |
| 암반 내구 | 세그먼트당 ×1.058 |
| 장비 가격 | 레벨당 ×1.34 |
| 드릴·광차 출력 | 레벨당 대체로 ×1.12 |
| 정련 | 장비 6레벨마다 ×2.5 |

광석은 약 10.24세그먼트, 약 41m마다 두 배가 된다.

### 2.2 정련이 없으면 지수적으로 정체한다

한 세그먼트의 광석이 사는 장비 레벨은 약 0.2312이고, 이 레벨이 만드는 출력 증가는 세그먼트당 약 ×1.0265다. 내구는 ×1.058이므로 암반 한 개를 깨는 시간은 세그먼트마다 약 3.064% 증가한다.

```text
1.058 / 1.026545 = 1.03064
```

- 100세그먼트 후: 약 20.5배 느림
- 300세그먼트 후: 약 8,557배 느림

따라서 정련은 부가 기능이 아니라 현재 장기 성장 사양의 필수 축이다.

### 2.3 정련을 포함하면 완만하게 발산한다

정련은 6레벨마다 ×2.5이며 이를 포함하면 세그먼트당 출력 증가가 약 ×1.0634가 된다.

```text
1.0634 / 1.058 ≈ 1.0051
```

즉, 세그먼트마다 채굴 속도가 약 0.51% 빨라지고 약 540m마다 속도가 두 배가 된다. 초반을 즉시 파괴하지 않으면서 장기적으로 발산하는 방향은 타당하다.

### 2.4 실제 앱은 시뮬레이터의 곡선을 재현하지 못한다

밸런스 시뮬레이터는 해금된 정련을 자동 구매한다. 반면 앱에는 정련 구매 UI가 없다. 따라서 문서에 기록된 180일 215~486km 곡선은 Core의 가능성이지 현재 앱의 재현 가능한 플레이 곡선이 아니다.

정련 UI가 들어가기 전에는 장기 성장 전환을 제품 완료로 판정하면 안 된다.

## 3. P0 수치 결함

### 3.1 장비·정련 비용의 `Double` 오버플로

장비 가격은 `1.34^레벨`을 `Double`로 계산한다. 약 레벨 2,410, 해금 심도 약 36km부터 범위를 벗어날 수 있다. 이 지점은 90일·180일 시뮬레이션 범위 안이다.

현재 `BigNumber`는 비유한 `Double`을 입력받으면 0으로 정규화한다. 이 동작과 `Double` 비용 비교가 결합하면 다음 위험이 있다.

1. 가격이 `inf`가 된다.
2. `BigNumber(inf)`가 0이 된다.
3. 지갑 비교가 `wallet >= 0`처럼 동작할 수 있다.
4. 차감도 0에 가까운 효과가 될 수 있다.

따라서 광석 기반 비용은 전부 `BigNumber`로 바꿔야 한다.

대상:

- `UpgradeQuote.cost`
- `UpgradePurchaseResult`의 cost/required/available
- `RefinementPurchaseResult`의 cost/required/available
- 장비·정련 가격 계산
- 추천 강화 비용·효율 계산
- 프레스티지 손실 광석
- 화면의 비용 표시

### 3.2 램프 정련 배수의 `Double` 오버플로

드릴과 광차 정련은 `BigNumber`를 사용하지만 램프 정련은 `pow(2.5, tier * 0.5)`를 `Double`로 계산한다. 장기 구간에서 `inf`가 되면 크리티컬 데미지 계산이 0 또는 잘못된 값으로 축약될 수 있다.

권장 구조:

```swift
struct StrikePower {
    let tapDamage: BigNumber
    let damagePerSecond: BigNumber
    let criticalChance: Double
    let criticalMultiplier: BigNumber
}
```

확률만 `Double`, 크기를 나타내는 배수와 보상은 `BigNumber`로 유지한다.

### 3.3 플레이어 표면의 `doubleValue` 제거

메인 지갑은 큰 수 포맷터를 사용하지만 다음 화면은 아직 `doubleValue`를 거친다.

- 현재 암반 예상 보상
- 탭·자동 데미지 HUD
- 부유 데미지·광석 숫자
- 프레스티지 손실 미리보기
- 일부 CLI·보고서

큰 수는 모든 화면에서 `DeepMineNumberFormatter.string(big:)`로 통일한다.

## 4. 쿠키클리커식 체감이 약한 이유

### 4.1 현재 값은 보이지만 변화율이 보이지 않는다

다음 정보를 홈에서 지속적으로 보여줘야 한다.

- 광석/초
- 층/초 또는 평균 파쇄 시간
- 최근 구매 전후 변화율
- 다음 정련까지 남은 레벨
- 정련 시 얻는 ×2.5 배수
- 지난 프레스티지 대비 현재 출력 배수

구매 직후 예시:

```text
광석/초 +25.0%
현재 암반 8.2초 → 6.6초
드릴 정련 4단계 · 전체 탭 출력 ×2.5
```

큰 숫자보다 **얼마나 빨라졌는가**가 먼저 읽혀야 한다.

### 4.2 첫 자동화 시점이 늦을 수 있다

신규 플레이어는 광차 Lv.1에서 자동 생산이 0이고, Lv.2가 첫 자동화다. 웹 프로토타입은 방치 장면을 보여주기 위해 의도적으로 Lv.2에서 시작한다. 앱의 첫 자동화가 첫 플레이 30~90초 안에 오지 않는다면 다음 중 하나를 적용한다.

- 첫 광차만 비용 할인
- 첫 암반 보상에 광차 설치권 지급
- 온보딩 완료 보상 분리
- 추천 엔진에 `첫 자동화 해금` 절대 우선 규칙 추가

### 4.3 대량 구매가 없다

수천 레벨 경제에서 1회 1레벨 구매는 실제 플레이가 될 수 없다.

필수 구매 단위:

- ×1
- ×10
- ×100
- MAX
- 길게 눌러 연속 구매
- 프레스티지 후 기억 구간 일괄 재구매

장기적으로는 정련 우선·레벨 우선·균형 정책의 자동 구매를 영구 강화로 제공할 수 있다.

### 4.4 추천 엔진이 클리커 경제를 추천하지 않는다

현재 추천은 다음 집중 세션의 기대 광석 효율을 중심으로 계산한다. 홈의 클리커 추천은 별도로 만들어야 한다.

| 추천 종류 | 기준 |
|---|---|
| 빠른 파쇄 | 현재 암반 ETA 감소 / 비용 |
| 방치 강화 | 자동 DPS 또는 광석/초 증가 / 비용 |
| 큰 도약 | 첫 자동화, 정련, 장비 분기 등 단계 해금 |

## 5. UI 리뷰

### 5.1 유지할 부분

- 갱도를 홈의 주 대상으로 유지
- 현재 지반을 큰 기본 탭 대상으로 유지
- 약점만 별도 버튼으로 유지
- 예상 보상과 ETA를 갱도 바로 아래 유지
- 집중 증폭기를 접힌 선택 경로로 유지
- 네 안료와 황동 희소성 규칙 유지

### 5.2 수정할 부분

#### 심도 잠금과 최대 상태 분리

심도 잠금 상태에서 비용이 `nil`이 되며 버튼 제목이 최대 레벨처럼 보일 수 있다. 상태를 명시적으로 분리한다.

```swift
enum EquipmentPurchaseAvailability {
    case purchasable(cost: BigNumber)
    case depthLocked(requiredDepth: Int)
    case arithmeticBound
}
```

#### 부유 데미지의 `−` 제거

`−12`는 플레이어 자원 손실처럼 읽힐 수 있다. `12 피해`, 숫자만 표시, 또는 일반 타격 숫자 축소를 검토한다.

#### 심도 단위 포맷

- 0~999m: `842m`
- 1~999km: `4.82km`
- 이후: 공학 표기 또는 고유 심층 단위

#### 면 단위 충격 잔상 확대

실제 압축은 60~80ms를 유지하되 충격 윤곽·균열 밝기 잔상을 추가 100~180ms 남긴다. 새 색 없이 시간과 면적만 조정한다.

## 6. 이미지 에셋 리뷰

### 6.1 기술 품질

대표 에셋은 1x/2x/3x, lossless, original rendering, nearest-neighbor 렌더링과 이진 알파를 사용한다. `MinerMiningStrip`은 96×96 네 프레임으로 실루엣 차이가 충분하고, `ShaftRock_entry`는 와이드 지층 배경으로 적합하다.

개별 품질보다 장기 배치가 문제다.

### 6.2 장기 진행보다 에셋이 먼저 소진된다

- 마지막 지역인 심연은 1,600m부터 시작
- 30일 라이트도 2,728m
- 장비 외형은 Lv.15 이후 같은 3티어
- 작업조·광차·조명도 작은 최대치에서 정지

수백 km까지 성장하는 경제와 시각적 세대가 맞지 않는다.

### 6.3 권장 에셋 확장 방식

전체 완성 이미지를 무한히 늘리지 말고 기본층 + 모듈 오버레이로 확장한다.

#### 장기 지역 세대

| 구간 | 시각 주제 |
|---|---|
| 0~240m | 입구 암반 |
| 240~800m | 수정층 |
| 800m~1.6km | 폐허층 |
| 1.6~5km | 심연 I |
| 5~20km | 압착층·심연 II |
| 20~100km | 고대 단층·매몰 설비 |
| 100km 이상 | 심핵·비현실 지질 |

#### 정련 오버레이

- 정련 1: 황동 날
- 정련 3: 이중 비트
- 정련 5: 압축 링
- 정련 10: 코어 발광 홈
- 정련 20: 심층 작업 프레임

드릴·광차·램프 각각 4~6개의 오버레이로 수천 레벨의 성장을 표현한다.

#### 프레스티지 영구 흔적

- 깊이 기록판
- 영구 케이블·지지대
- 기억 링
- 지표 기지 증축 단계
- 과거 최고 심도에 남는 황동 표식

## 9. 완료 판정 기준

1. 신규 플레이어가 30~90초 안에 첫 자동 생산을 연다.
2. 첫 정련이 첫 플레이 5~10분 안에 보이고 구매 가능하다.
3. 정련 구매 직후 ×2.5와 암반 ETA 변화가 함께 보인다.
4. 시뮬레이터의 연속 구매 정책을 앱의 MAX 구매로 재현할 수 있다.
5. 40km·150km·500km 픽스처에서 비용이 `inf`, `—`, 무료 구매가 되지 않는다.
6. 같은 구간에서 크리티컬 데미지가 0이나 비유한 값이 되지 않는다.
7. 플레이어 표면에서 큰 광석·데미지에 `.doubleValue`를 직접 사용하지 않는다.
8. Lv.15 이후에도 정련·프레스티지에 따라 장비와 작업장이 변한다.
9. 1.6km 이후 최소 세 개 이상의 장기 지질 세대가 존재한다.
10. 구매할 때마다 숫자, 시간, 설비, 연출 중 최소 하나가 눈에 띄게 변한다.
11. 30/90/180일 결과가 실제 앱 구매 정책으로 재현된다.
12. main 푸시마다 Core·웹·에셋·패리티 검사가 자동 실행된다.
