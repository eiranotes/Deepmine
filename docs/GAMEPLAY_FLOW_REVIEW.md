## 구현 후속 판정 — 2026-08-02 current audit

최초 리뷰 뒤 다음 흐름 결함은 해소됐다.

- 자동화 전 추천은 더 싼 드릴 대신 첫 광차 ◆180 저축 목표를 유지한다
- 정련 구매와 장비 ×10/×100/MAX가 앱에 있고, 정련은 전용 성공 피드백을 쓴다
- 집중 시작 준비부터 활성 종료까지 홈 타이머·오프라인 정산을 막아 같은 시간을 두 번 지급하지 않는다

- 구매 결과와 추천 비용이 `Double` 포화 대신 실제 `BigNumber`를 전달한다
- 홈이 자동 광석/초·층/초, 구매 전후 출력·ETA·증가율을 보여 준다
- 심연 내부 5/20/100km 지질과 versioned v2 에셋을 앱·웹에 연결했다
- 일반 저장·원자적 명령·세션 종료에서 기억 장비·정련 단계·달성 업적을 보존한다

계속 남는 핵심:

- 집중 세션은 여전히 같은 `MiningLoop`에 배수를 거는 구조가 아니라 별도 보상 경제다.
  single-clock은 이중 지급만 막았으며 두 경제를 통합한 것은 아니다
- 통계와 도전과제의 세션 중심 비중이 일부 남는다
- 정련 MAX와 프레스티지 뒤 기억 정련 재설치가 없다
- 프레스티지 손실 고지와 재구축 홈 진입의 전체 실화면 회귀가 필요하다
- 실제 UI 구매 정책을 쓰는 30/90/180일 장기 시뮬레이션이 없다
- `NextStepPlanner`의 극후반 진행도는 아직 `Double`/`Int` 투영이다
- 옛 Lv.200 제품 상한은 제거됐지만 1,499,925m의 Lv.100,000 산술 안전 천장은 남는다
- 정련은 광석으로 분리되고 수정 테마 구매 경로는 생겼지만, 온보딩 첫 수정 1개를 곧바로
  쓸 수 없고 다음 소비 목표도 안내하지 않아 첫 수정의 즉시·명확한 소비처는 미완이다
- 전체 UI와 FamilyControls/AlarmKit/Live Activity 실기기 릴리스 게이트가 남아 있다

## 1. 결론

DeepMine의 **순간 플레이 루프**는 상당히 좋아졌다.

```text
암반 탭
→ 균열·전신 타격·접촉 피드백
→ 암반 파괴
→ 광석 획득·4m 하강
→ 장비 구매
→ 광차 자동 굴착
→ 오프라인 정산
```

그러나 **제품 전체 흐름**은 아직 두 게임이 겹쳐 있다.

1. 세로 갱도 중심의 방치형 클리커
2. 집중 세션을 완료하고 별도 보상을 받는 이전 생산성 게임

Claude의 수정은 1번을 실제 게임으로 만드는 데 성공했다. 반면 홈 추천, 집중 출정, 귀환 보고,
스트릭, 통계, 도전과제, 프레스티지 영구 강화의 상당 부분은 아직 2번의 데이터를 중심으로 움직인다.

따라서 현재 판정은 다음과 같다.

| 범위 | 판정 |
|---|---|
| 탭 한 번의 손맛 | 좋음 |
| 암반 하나의 폐루프 | 좋음 |
| 첫 자동화 전환 | 개념은 좋으나 안내 정책이 늦춤 |
| 오프라인 복귀 | 구조는 좋음 |
| 장비·갱도 시각 누적 | 초중반은 좋음 |
| 정련 지수 성장 | PR #3에서 실제 구매 가능, 체감·발견성은 부족 |
| 집중 증폭기 | 실제 광산과 분리된 별도 경제 |
| 메타 진행 | 집중 세션 의존도가 여전히 높음 |
| 프레스티지 | 기능은 완성됐으나 재구축 UX와 보상 축이 클리커에 덜 맞음 |
| 장기 게임 | 수식은 열렸으나 UI·수치 타입·콘텐츠 세대가 미완 |

핵심 수정 방향은 **집중 기능을 삭제하는 것**이 아니라, 집중 세션의 결과를 별도 광석 지급에서
실제 갱도 가속으로 통합하는 것이다.

# 2. 현재 실제 플레이 흐름

## 2.1 최초 실행과 온보딩

현재 흐름:

```text
앱 실행
→ 설명 페이지 없이 실제 첫 암반 표시
→ 암반 직접 탭
→ 0m에서 4m로 하강
→ 첫 광맥 확정 공개
→ 지갑을 광석 100으로 보정
→ 드릴 Lv.1 → Lv.2 설치
→ 권한 요청 없이 홈 진입
```

### 잘된 점

- 첫 상호작용이 설명 버튼이 아니라 실제 채굴이다.
- 온보딩용 가짜 미니게임이 아니라 제품의 `MiningLoop`를 그대로 사용한다.
- 첫 암반, 보상, 광맥, 장비 구매가 실제 저장소에 기록된다.
- Claude 수정으로 작업면이 카드 밖에 잘리던 결함이 해결됐다.
- 집중 차단·알림 권한은 더 이상 게임 진입 게이트가 아니다.
- 첫 암반 보상으로 정확히 첫 드릴 강화를 구매하게 만들어 다음 행동이 명확하다.

### 남은 문제

#### A. 첫 광맥이 지급하는 수정의 즉시·명확한 용도가 없다

현재 구매 경로를 대조하면:

- 장비: 광석
- 장비 분기: 광석
- 정련: 광석
- 영구 강화: 코어 조각
- 테마: 수정 3/6/10개 구매 또는 심도·도전과제 해금

이다. 정련이 수정에서 광석으로 옮겨진 뒤에도 테마 구매라는 후속 소비 경로는 있다.
하지만 첫 온보딩 보상은 수정 1개라 가장 싼 테마의 3개에도 못 미치고, 화면은 이를
저축 목표나 외형 구매로 연결하지 않는다. 테마가 심도로 먼저 해금될 수도 있어 구매 경로의
필요성도 약하다. 그런데 온보딩은 수정을 게임의 핵심 희귀 보상처럼 가르친다.

따라서 첫 플레이어는 곧바로 **나중 소비처는 있지만 지금 무엇을 위해 모으는지 불명확한 통화**를 받는다.

권장안:

- 수정을 외형·갱도 장식·정련 외형 오버레이의 전용 통화로 만든다.
- 또는 수정 통화를 제거하고 첫 광맥 보상을 실제 사용 가능한 해금 토큰으로 바꾼다.
- 정련을 다시 수정으로 사게 하는 것은 세션 수 차이를 지수 증폭시키므로 피한다.

#### B. 온보딩 타격 숫자는 아직 이전 표기다

PR #3은 홈 타격 숫자의 `−` 기호와 `doubleValue` 손실을 고쳤지만,
`OnboardingFlowView+Steps.swift`는 여전히 `−데미지`와 `doubleValue`를 사용한다.
초반에는 수치 범위 문제가 없지만 같은 행동이 온보딩과 홈에서 다른 표기를 쓴다.

## 2.2 온보딩 직후 수동 채굴

온보딩 종료 상태:

```text
현재 심도: 4m
광석: 0
드릴: Lv.2
광차: Lv.1
램프: Lv.1
자동 굴착: 0
```

홈 순서:

```text
광석 카운터
→ 갱도 HUD
→ 실제 암반
→ 현재 암반 보상 / 남은 탭 또는 자동 ETA
→ 장비 3종 요약
→ 추천 강화 1탭 버튼
→ 장비·통계·도전과제
→ 접힌 집중 증폭기
```

### 잘된 점

- 광산 장면이 홈의 주역이다.
- 현재 암반이 얼마를 주는지 바로 보인다.
- 광차가 없을 때 가짜 자동 ETA 대신 남은 탭 수를 보여 준다.
- 약점·크리티컬·임팩트 미터가 능동 플레이의 보상을 만든다.
- 첫 공명 결절은 약 5.2초 뒤 나타나므로 초반에 간헐 보상을 학습한다.
- 공명 결절은 고정 보상이 아니라 현재 탭·자동 출력을 18초 동안 두 배로 만든다.

### 남은 문제

#### A. 첫 자동화를 홈 추천이 늦춘다

제품 규칙은 명확하다.

> 광차 Lv.1은 자동 생산 0, 광차 Lv.2가 방치 채굴의 시작이다.

그러나 홈 추천은 현재 암반 ETA나 광석/초가 아니라 **다음 집중 세션의 기대 광석 효율**을 계산한다.
드릴은 세션 보상을 1레벨당 약 12% 올리고, 광차는 25분 세션에서 약 5% 올리므로
추천은 초반 드릴을 우선한다.

현재 상수로 단순 재현한 결과:

| 정책 | 첫 광차 Lv.2 시점 |
|---|---:|
| 다른 구매 없이 광차만 저축 | 약 88m |
| 밸런스 시뮬레이터의 최저가 구매 | 약 104m |
| 현재 홈 추천을 계속 따름 | 약 128m, 드릴 Lv.5 뒤 |

계산은 암반 광석과 실제 가격·심도 잠금을 사용한 단순 결정적 재현이다. 크리티컬과 약점은
소요 탭 수를 바꾸지만 광석 구매 순서의 구조적 차이는 그대로다.

첫 자동화는 방치형 게임의 가장 중요한 전환이므로 다음 중 하나가 필요하다.

- 자동화 미보유 상태에서는 광차 Lv.2를 추천 1순위로 고정
- 추천을 `현재 암반 ETA 감소 / 비용`과 `자동 DPS 증가 / 비용`으로 재작성
- 온보딩 직후 광차 설치권이나 첫 구매 할인 제공
- 추천 UI에 `방치 시작`이라는 별도 마일스톤 배지 표시

#### B. 현재 성장은 크기보다 상태값으로만 보인다

HUD는 탭 데미지와 자동 데미지를 보여 주지만 다음이 없다.

- 광석/초
- 층/분 또는 층/초
- 이번 구매 전후 ETA
- 이번 구매 전후 생산 증가율
- 다음 정련까지 남은 레벨

클리커의 만족은 숫자 자체보다 **이전보다 얼마나 빨라졌는가**에서 나온다.

## 2.3 첫 광맥층·장비 분기·초기 자동화

주요 초기 마일스톤:

| 마일스톤 | 위치/조건 |
|---|---:|
| 첫 광맥층 | 100m, 25세그먼트 |
| 수정 지역 | 240m |
| 첫 프레스티지 자격 | 한 런 120세그먼트 = 480m |
| 폐허 지역 | 800m |
| 심연 지역 | 1,600m |
| 장비 분기 | 해당 장비 Lv.5 |
| 첫 정련 | 해당 장비 Lv.7부터 구매 가능 |

첫 광맥층은 내구 ×6, 보상 ×15이므로 좋은 초반 피크다. 이 보상으로 장비를 여러 번 설치하면서
광산 설비가 확장되는 장면도 강하다.

### 장비 분기의 장점

- 드릴: 확폭 / 충격
- 광차: 함대 / 화물
- 램프: 조사 거리 / 행운

선택 결과가 수치뿐 아니라 보어 폭, 광차 수, 적재량, 조명, 약점 광택에 반영된다.
이는 Claude가 잘 통합한 부분이다.

### 장비 분기의 UX 위험

분기는 한 런 동안 되돌릴 수 없는 상호배타적 선택인데 버튼을 누르면 즉시 구매된다.
실수 방지 확인이나 `프레스티지 전까지 변경 불가` 안내가 충분한지 화면 검증이 필요하다.

권장안:

```text
선택 전
- 현재 출력
- 선택 후 출력
- 갱도 외형 미리보기
- 이번 런 동안 변경 불가
```

를 한 번에 보여 준 뒤 설치한다.

## 2.4 정련과 지수 성장

Claude 수정으로 Core에는 다음 축이 생겼다.

```text
장비 6레벨 간격
→ 정련 1등급 구매 가능
→ 해당 출력 ×2.5
```

PR #3에서 실제 앱 구매 경로도 추가됐다.

```text
장비 화면
→ 정련 패널
→ 드릴/광차/램프 R등급 확인
→ 해금 레벨 또는 비용 확인
→ 구매
→ 저장
```

### 좋아진 점

- 시뮬레이터만 사용하던 정련을 실제 플레이어도 구매할 수 있다.
- 명령 ID를 사용해 재시도 중 중복 구매를 막는다.
- 잠금·부족 광석·성공·저장 실패 경로가 연결됐다.
- 메인 광석과 HUD·부유 숫자의 큰 수 지수가 PR #3에서 보존된다.

### 남은 문제

#### A. 시뮬레이터와 실제 플레이 정책이 다르다

밸런스 시뮬레이터는:

```text
가장 싼 장비를 가능한 만큼 구매
→ 해금된 정련을 전부 즉시 구매
```

한다.

실제 홈은:

```text
다음 집중 세션 기대 보상 효율이 가장 높은 장비 1개 추천
→ 정련은 별도 장비 화면 아래쪽에서 사용자가 직접 발견
```

이다.

따라서 30/90/180일 곡선은 현재 실제 UI가 유도하는 정책을 검증하지 않는다.

필요한 검증 정책:

1. 홈 추천만 따르는 플레이어
2. 가장 싼 항목을 사는 플레이어
3. 정련 우선 플레이어
4. 자동화 우선 플레이어
5. 아무 것도 사지 않는 플레이어
6. 실제 `MAX` 구매 정책

#### B. 정련이 큰 사건처럼 보이지 않는다

현재 정련 행은 `R0 → R1`, `×2.5`, 가격을 보여 주지만:

- 구매 전후 ETA 없음
- 생산 증가율 없음
- 갱도 장비 외형 변화 없음
- 전용 햅틱·충격·설치 연출 없음
- 홈의 다음 목표에 노출되지 않음

×2.5는 일반 레벨 여러 개보다 큰 도약이므로 별도 사건으로 다뤄야 한다.

#### C. 후반 비용은 여전히 `Double`

지갑과 데미지는 `BigNumber`지만 장비·정련 비용과 부족 광석 결과는 `Double`이다.
장기 시뮬레이션 범위에서 오버플로가 가능한 구조이므로 비용 계열 전체를 `BigNumber`로 옮겨야 한다.

#### D. 대량 구매가 없다

장비가 수백·수천 레벨로 가는 설계인데 실제 UI는 한 번에 1레벨만 구매한다.
프레스티지 뒤 재구축까지 고려하면 다음이 P0다.

```text
×1 / ×10 / ×100 / MAX
길게 눌러 연속 구매
장비 우선 / 정련 우선 / 균형 정책
```

## 2.5 집중 증폭기 흐름

현재 흐름:

```text
홈 하단의 접힌 집중 증폭기 열기
→ 오늘 목표 확인
→ 안전/심층/탐사 선택
→ 15/25/50분 선택
→ 예상 세션 광석·광맥 확률·권한 상태 확인
→ 집중 세션 시작
→ 휴대전화를 내려놓는 카운트다운
→ 완료 또는 중도 포기
→ 별도 광석 보상·광맥·스트릭·도전과제 귀환 보고
```

### Claude 수정으로 좋아진 점

- 기본 홈 위계에서 집중이 내려갔다.
- 권한이 없어도 클리커와 프레스티지가 가능하다.
- 예상 보상, 0.75 개방 상태, 중도 포기 결과를 미리 보여 준다.
- 활성 화면은 사용을 유도하지 않고 내려놓으라고 명시한다.
- 세션 재개·중복 완료·귀환 보고 저장 경로가 견고하다.

### 구조적 문제: 증폭기가 실제 광산을 증폭하지 않는다

현재 집중 세션은 실제 갱도에 배수를 걸지 않는다.

- `ShaftView`의 출력 배수는 공명 결절만 읽는다.
- 집중 세션은 별도 `RewardCalculator`가 광석을 계산한다.
- 완료 시 실제 암반을 파지 않고 지갑에 광석을 직접 넣는다.
- 세션 동안 실제 갱도에 적용된 출력 변화가 화면에 없다.
- 정련 등급은 세션 보상 계산에 포함되지 않는다.

즉, UX에서 말하는 `집중 증폭기`는 실제로는 **별도 광석 지급 미니게임**이다.

이 때문에 다음 UI도 어긋난다.

- 귀환 보고의 심도 증가: 세션이 암반을 파지 않으므로 일반적으로 0
- 다음 지역 안내: 세션 보상과 직접 인과가 없음
- 홈 추천: 실제 채굴이 아니라 다음 세션 보상을 최적화
- 성장 통계: 실제 광산보다 세션당 광석을 추적

### 권장 통합안

집중 세션을 없애지 않고 다음처럼 바꾼다.

```text
집중 시작
→ 현재 갱도에 `sealed/open` 출력 배수 적용
→ 같은 MiningLoop가 실제 암반을 파괴
→ 실제 광석·심도·광맥층·도전과제 진행
→ 종료 보고는 세션 동안 실제로 이동한 값만 표시
```

예시:

| 상태 | 실제 갱도 효과 |
|---|---:|
| 권한 없이 개방 | 현재 탭·자동 출력 ×1.15 |
| 봉인 채굴 | 현재 탭·자동 출력 ×1.50 |
| 심층 계획 | 출력 ×1.80, 중도 종료 시 부스트 정산 없음 |
| 탐사 계획 | 출력 ×1.20, 광맥 사건 확률 증가 |

이 구조는 기존 세션·권한·Live Activity·귀환 보고를 재사용하면서 두 경제를 하나로 합친다.

## 2.6 귀환 보고

```text

실제 광석

다음 정련 또는 프레스티지까지 거리
```

## 2.7 오프라인 복귀

현재 흐름:

```text
앱 이탈
→ 마지막 정산 시각 저장
→ 최대 8시간, 효율 75%로 같은 자동 채굴 엔진 실행
→ 광석·층·광맥층 정산
→ 1분 이상이며 실제 보상이 있으면 복귀 시트
```

### 잘된 점

- 화면 자동화와 오프라인이 같은 `MiningLoop.advance`를 사용한다.
- 시계 역행·비정상 미래 시간을 거부한다.
- 8시간 상한을 숨기지 않고 말한다.
- 긴 정산의 512층 절단 손실을 최대 12패스로 재적용한다.
- 실제로 아무 자동 장비가 없으면 빈 보상을 보여 주지 않는다.

### 남은 문제

- PR #3이 홈의 큰 수 표기는 고쳤지만 `OfflineReturnSheet`는 아직
  `oreGained.doubleValue`를 사용한다.
- 복귀 시트가 현재 심도 전후, 새 지역, 새 장비 해금, 정련 해금을 보여 주지 않는다.
- 장비·통계·집중 화면으로 이동한 동안 루트 `ShaftView` 타이머가 계속 동작하는지 E2E가 없다.
  만약 SwiftUI가 루트를 멈추거나 재생성하면 같은 앱 안에서 보낸 시간이 정산되지 않을 수 있다.

필수 E2E:

```text
홈 심도 기록
→ 장비 화면에서 60초 체류
→ 홈 복귀
→ 자동 생산 60초분이 보존됐는지 확인

홈 심도 기록
→ 집중 세션 화면에서 60초 체류
→ 홈 복귀
→ 기본 자동 생산과 집중 배수가 정확히 반영됐는지 확인
```

## 2.8 통계·도전과제·스트릭

Claude는 화면상 집중을 보조 기능으로 내렸지만, 메타 시스템은 아직 세션 중심이다.

### 통계

현재 통계의 중심:

- 완료 세션 수
- 세션 귀환 심도
- 세션에서 얻은 광석
- 계획 비율
- 광맥 이력
- 주간 세션당 광석 성장

빠진 클리커 지표:

- 평생 부순 암반
- 평생 암반 광석
- 현재 광석/초
- 최고 층/초
- 오프라인 생산
- 정련 등급
- 광맥층 파괴 수
- 프레스티지 재구축 시간
- 공명 결절 수령률

### 스트릭

`MiningStreak` 주석은 `플레이어가 채굴한 날`이라고 설명하지만 실제 `record()` 호출은
집중 세션 완료 경로에 있다. 일반 탭, 자동 굴착, 오프라인 복귀는 스트릭 일수를 만들지 않는다.

따라서 현재 스트릭은 이름만 채굴 스트릭이고 실질적으로는 **집중 세션 스트릭**이다.

### 도전과제

총 35개 가운데 집중 없이 확실히 진행되는 것은 현재 구조상 대략 11개다.

- 첫 프레스티지 1개
- 심도 5개
- 장비·균형 5개

나머지 다수는 다음을 요구한다.

- 집중 시간
- 집중 세션 수
- 심층·탐사 세션
- 봉인 완료
- 세션 광맥
- 세션이 기록하는 스트릭·채굴일

즉, 권한 없이 코어 진행은 가능하지만 **메타 콘텐츠의 대부분은 선택형 기능 밖에 있지 않다.**

### 장식 보상 가시성

`MineDecorationScene`은 존재하지만 현재 검사한 홈·갱도 렌더 경로에서는 호출이 확인되지 않았다.
도전과제와 금고 광맥이 주는 장식이 실제 주 화면에 보이는지 다시 연결 검증이 필요하다.

### 수정 통화

도전과제와 광맥은 수정을 계속 지급하고 3/6/10개짜리 테마 구매 경로도 있다.
다만 첫 보상 1개는 즉시 쓸 수 없고 다음 테마 저축 목표가 노출되지 않으며, 심도 해금과
구매가 겹쳐 플레이어에게 수정 소비 결정을 명확히 가르치지 못한다.

## 2.9 프레스티지

현재 흐름:

```text
한 런에서 목표 세그먼트 파괴
→ 설정 안의 심층 진입 화면
→ 손실 확인
→ 지표로 복귀
→ 코어 조각 획득
→ 영구 강화 선택
→ 반값 기억 할인으로 장비 재구축
```

### 잘된 점

- 프레스티지 자격은 집중이 아니라 실제 부순 암반으로 계산한다.
- 현재 심도는 0으로 돌아가지만 최고 심도와 지역·도전과제는 유지된다.
- 늦게 프레스티지해도 더 많은 코어 조각을 받는다.
- 이전 최고 장비까지 재구매 비용이 절반이다.
- 손실 확인과 영구 강화 배분이 분리돼 있다.

### 남은 문제

#### A. 접근 경로가 설정 안에 숨겨져 있다

프레스티지는 코어 게임의 핵심 반복인데 홈의 진행 화면이 아니라 설정 안에 있다.
자격이 생기면 홈에 `심층 진입 가능`을 보여 줘야 한다.

#### B. 손실 고지가 불완전하다

화면은 광석·세그먼트·현재 심도·장비를 보여 주지만 실제 엔진은 추가로 다음을 초기화한다.

- 장비 분기
- 정련 등급

특히 정련은 장기 출력의 핵심이므로 반드시 손실 목록에 표시해야 한다.

#### C. 재구축 입력 노동

프레스티지 후 장비·정련을 한 단계씩 다시 사야 한다. 수백 레벨 이후에는 반값 할인보다
입력 횟수가 더 큰 비용이 된다.

필수 기능:

```text
기억된 장비까지 MAX 재설치
기억된 정련까지 재설치
한 번에 예상 비용 표시
장비 우선/정련 우선 정책
```

#### D. 영구 강화 3개 중 2개가 집중 세션 중심

- 굴착 기억: 실제 클리커 출력 증가
- 공명 탐지: 세션 광맥 확률 중심
- 압축 시간: 50분 집중 세션 보상 중심

집중을 전혀 쓰지 않는 플레이어에게는 사실상 한 선택지만 있다.

클리커용 영구 강화 예시:

- 굴착 기억: 전체 출력
- 자동 정비: 오프라인 효율·상한
- 지층 분석: 광맥층 보상·약점
- 재설치 공정: 기억 장비 자동 구매
- 공명 축전기: 공명 결절 지속시간 또는 배수

## 2.10 장기 게임

### 수식

정련을 포함하면 장기 가속 구조는 성립한다.

- 장비 단독: 암반 내구보다 뒤처져 장기 정체
- 정련 포함: 세그먼트당 약 0.5%의 양의 성장 여유
- 지갑과 데미지: `BigNumber`

### 실제 흐름의 장기 결함

- 장비·정련 비용은 `Double`
- 램프 크리티컬 정련 배수는 `Double.pow`
- 대량 구매 없음
- 장비 외형은 Lv.15 이후 고정
- 지역은 1,600m 이후 심연 하나
- 작업조·광차·램프 수량은 초반에 시각 상한 도달
- 심도는 계속 `m`로 표시
- 90/180일 실제 UI 정책 검증 없음

수학적 무한 성장과 플레이 가능한 무한 성장은 아직 같지 않다.

## 3.2 Claude 수정 뒤에도 남은 것

Claude는 클리커 루프를 새로 만드는 작업을 매우 잘했지만, 기존 제품의 주변 시스템을
클리커에 완전히 재배선하지는 않았다.

남은 대표적 이중 구조:

| 클리커 중심 | 아직 세션 중심 |
|---|---|
| 실제 암반 심도 | 홈 추천 |
| 자동·오프라인 채굴 | 집중 보상 계산 |
| 정련 | 귀환 성장 지표 |
| 보어·설비 | 통계 |
| 암반 기준 프레스티지 | 스트릭 |
| 공명 결절 | 대부분의 도전과제 |
| BigNumber 지갑 | 세션·비용·프레스티지의 Double 경로 |

따라서 다음 단계는 새로운 기능을 더 얹기보다 **주변 시스템을 하나의 광산 경제에 합치는 작업**이어야 한다.

# 4. 수정 우선순위

## P0 — 전체 흐름을 하나의 게임으로 만들기

1. 홈 추천을 실제 채굴 효율 기준으로 교체
2. 자동화 미보유 시 첫 광차를 최우선 마일스톤으로 처리
3. 집중 세션을 별도 광석 지급이 아니라 실제 `MiningLoop` 배수로 통합
4. 귀환 보고를 실제 세그먼트·심도·광석 중심으로 전환
5. 스트릭을 실제 채굴일 또는 복귀일 기준으로 전환
6. 통계와 도전과제를 클리커 지표 중심으로 재편
7. 수정 통화의 소비처를 정의하거나 제거
8. 프레스티지 손실에 정련·분기 표시
9. 장비·정련 `MAX` 구매와 프레스티지 재설치
10. 모든 광석 비용과 크리티컬 배수를 `BigNumber`로 전환
11. 장비·집중 화면에서 홈 자동 채굴이 계속되는지 E2E 추가
12. OfflineReturnSheet·Onboarding 등 남은 `doubleValue` UI 경로 정리

## P1 — 성장 체감

1. 광석/초·층/분 HUD
2. 구매 전후 ETA·생산 증가율
3. 정련 ×2.5 전용 연출
4. 프레스티지 전후 재구축 시간 비교
5. 5km·20km·100km 이상 지질 세대
6. 정련·프레스티지 기반 장비 외형 오버레이
7. km 이상 심도 단위 포맷
8. 장식 보상 실제 갱도 재연결

## P2 — 장기 운영

1. 실제 UI 정책 30/90/180일 시뮬레이션
2. 홈 추천·MAX 구매·자동 구매 정책별 비교
3. 문서와 코드의 오래된 집중/수정 설명 정리
4. README에 실제 플레이 흐름과 현재 제한 명시
5. CI의 `.build` 줄 수 오탐과 Sites 전용 Vite 플러그인 문제 해결

# 5. 권장 최종 플레이 흐름

```text
[첫 실행]
실제 암반 파괴
→ 첫 광맥
→ 드릴 설치
→ 홈

[첫 2~5분]
직접 채굴
→ 첫 공명 결절
→ 첫 광맥층
→ 광차 설치
→ 자동 채굴 시작

[초기 성장]
장비 레벨
→ 장비 분기
→ 첫 지역
→ 첫 정련 ×2.5
→ 첫 오프라인 복귀

[선택형 집중]
집중 시작
→ 실제 광산 출력 배수
→ 같은 암반·같은 광석·같은 심도 진행
→ 실제 결과 보고

[중기]
지역 전환
→ 정련 반복
→ 갱도 설비 확장
→ 암반·자동화·정련 도전과제
→ 첫 프레스티지

[프레스티지]
손실·유지 항목 완전 공개
→ 코어 조각
→ 클리커 영구 강화
→ 기억 장비 MAX 재설치
→ 더 빠른 새 하강

[장기]
새 지질 세대
→ 생산 속도 폭발
→ 정련·프레스티지 외형 누적
→ 수백 km 이후에도 새 목표 유지
```

# 6. 완료 판정 기준

다음 조건을 만족해야 전체 흐름이 클리커 피벗을 완료했다고 볼 수 있다.

- [ ] 신규 플레이어가 홈 안내를 따르면 첫 자동화를 의도한 시간 안에 연다.
- [ ] 추천 버튼이 실제 암반 ETA 또는 광석/초를 개선한다.
- [ ] 집중 세션이 실제 갱도에 같은 엔진으로 반영된다.
- [ ] 집중 없이도 스트릭·통계·도전과제의 주된 메타 루프가 성립한다.
- [ ] 수정 통화에 명확한 소비 결정이 있다.
- [ ] 정련 구매가 홈의 다음 목표로 노출되고 ×2.5 변화가 보인다.
- [ ] 프레스티지가 초기화하는 모든 항목을 사전에 보여 준다.
- [ ] 프레스티지 후 한 번에 재구축할 수 있다.
- [ ] 비용·배수·표시가 40km·150km·500km에서도 오버플로하지 않는다.
- [ ] 홈이 가려진 화면에서도 자동 채굴 시간이 보존된다.
- [ ] 오프라인·온보딩·프레스티지·귀환의 큰 수 표기가 일관된다.
- [ ] 30/90/180일 시뮬레이션이 실제 UI 구매 정책을 사용한다.
- [ ] 1,600m 이후에도 시각·목표·보상 세대가 이어진다.
