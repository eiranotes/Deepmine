# Defects and Release Gates

업데이트: 2026-08-02 (current audit)

## 2026-08-02 current audit disposition

이번 감사에서 수정하고 집중 회귀로 고정한 결함:

- 활성 집중 세션과 시작 버튼의 비동기 준비 구간에도 숨은 홈 `ShaftView`와 오프라인 정산이
  계속 돌아 같은 시간을 이중 지급할 수 있던 결함. 복구→정산을 직렬화하고 시작 준비부터

  남기던 결함. 유한 예산을 68,096세그먼트로 넓히고 잔여를 버리지 않는다
- 광석 134에서 구매 가능한 드릴 추천이 첫 광차 ◆180 저축을 깨던 결함
- 구매/부족/벌크/정련 결과와 추천 비용이 `Double`로 포화돼 깊은 구간의 실제 값을
  사용자 표면에 전달하지 못하던 결함
- `ShaftRock_pressure`와 `RefinementBadge_cart`의 손상 PNG, 7종 장기 진행 에셋의
  네 안료·알파·카탈로그 계약 위반
- deep geology가 5/20/100km의 정확한 경계가 아니라 viewport top 기준으로 늦게 바뀌던 결함
- Pages 권한이 PR build까지 전역 적용되고, Vinext 플러그인 소스가 Git에서 무시돼 clean
  checkout과 로컬 빌드가 달라지던 결함
- 일반 저장 외의 원자적 명령·세션 종료 경로가 기억 장비·정련 단계·달성 업적을 저장하지 않아,
  구매 성공 뒤 R0으로 돌아가고 장기 진행이 소실되던 결함
- `Double(Int.max)`의 반올림 경계에서 남은 탭 수를 `Int`로 바꾸면 trap할 수 있던 결함
- 웹/Pages의 첫 광차 저축과 램프 정련 공식이 Core와 달라 같은 상태에서 다른 추천·배율을
  보여 주던 결함

열린 소프트웨어/제품 closeout:

- 실제 UI 구매 정책을 재현하는 30/90/180일 장기 시뮬레이션이 없다
- 집중 세션은 같은 `MiningLoop`에 배수를 거는 구조가 아니라 별도 보상 경제다. single-clock은

- `NextStepPlanner`의 극후반 목표 진행도는 아직 `Double`/`Int` 투영이다
- 웹은 JavaScript `number` formula harness여서 앱 `BigNumber`의 극후반 범위를 검증하지 않는다
- 전체 XCUITest와 프레스티지 재구축·장기 깊이 실화면 검증이 남아 있다
- 원격 Actions/Pages는 push 전이라 성공을 검증하지 않았다

## Confirmed simulator defects

수정한 주요 결함:

- **`BigNumber`가 자기 자신을 만들다 스택을 넘겼다.** `Double`을 왼쪽에 받는 비교 오버로드
  (`<(Double, BigNumber)`)를 추가하자, `BigNumber`의 초기화 안에 있는 `abs(scaled) < 1`의
  리터럴이 `Double`이 아니라 `BigNumber`로 추론됐다. 그것을 만들려고 초기화를 다시 호출해
  **첫 값을 만드는 순간 죽었다.** `Double` 좌변 오버로드는 정의하지 않는다 (D-069)
- **`Int(min(Double(Int.max), x))`가 트랩했다.** `Double(Int.max)`는 반올림되어 `Int.max`보다
  크므로, 클램프가 잡으려던 바로 그 값에서 변환이 죽는다. 지갑이 그만큼 커질 수 없어 잠재해
  있었고 무한 곡선이 매 런 그 크기에 도달한다 (D-069)
- **심연 광맥이 광석 없는 심도를 줬다.** `skipUnbrokenDepth(60)`이 15세그먼트를 건너뛰고 그
  층들은 영원히 광석을 주지 않았다. 세션이 6배 많은 헤비는 이것을 108회 받아 7,408m 중
  6,480m가 건너뛴 구간이었고, 그래서 심도는 1등인데 광석은 꼴찌였다. 게임에서 가장 귀한
  광맥이 장기적으로 손해였다. 수정 보상으로 바꿨다 (D-068)
- **곱연산 축을 세션 통화로 사게 했다.** 정련을 수정으로 사도록 설계했는데 수정은 광맥에서,
  광맥은 세션에서 나온다. ×2.5^n이 세션 수 차이를 지수로 증폭해 180일에 1.6e10배가 됐다.
  광석으로 옮겨 해소했다 (D-068)
- **밸런스 게이트가 잘못된 것을 재고 있었다.** 30일 누적 광석 1.5~20배 대역은 세션이
  경제이던 시절 기준이다. 클리커 경제에서 누적 광석은 심도의 지수 함수이므로 같은 게임을
  하는 두 플레이어가 자릿수 차이로 나타난다. 심도 기준으로 교체했다 (D-070)

- **긴 오프라인 정산이 실제로 부순 것보다 적게 지급했다.** `RockEngine.resolve`는 한 번에
  512세그먼트까지만 걷고 넘친 데미지를 버렸다. 호출부는 `wasTruncated`만 받고 남은 양을
  알 수 없었으며, 앱은 그 플래그조차 읽지 않아 손실이 조용히 일어났다. 잔여 데미지를
  반환하고 `MiningLoop.advance`가 최대 12패스까지 다시 적용하도록 고쳤다. (D-066)
  D-072에서 carry pass를 패스당 6,144세그먼트로 넓혔고, 150km·500km의 8시간 회귀는
  잔여 없이 끝난다. 옛 6,144 총상한은 역사적 기록이다.

- **첫 암반을 실제로 끝까지 깰 수 없었다.** 온보딩 카드가 갱도 씬을 고정 오프셋 48로 그려서,
  0m에서 24m 지표 inset 아래에 있는 작업면이 카드 밖으로 밀렸다. 암반은 바닥에 잘린 조각으로만
  보이고 카드 중심 — 탭이 실제로 떨어지는 지점 — 은 빈 갱도였다. 20회를 탭해도 데미지가 0이라
  `testFreshLaunchStartsOnTheBreakableRockAndPersistsTheReward`가 통과한 적이 없었다.
  헤드를 따라가도록 오프셋을 계산해 고쳤다. (D-063)
- **자동 굴착 중 광부가 예비동작 자세에서 얼어붙었다.** 자동화가 0.25초 시뮬레이션 스텝마다
  0.56초짜리 스윙을 재시작해, 곡괭이가 도달하기 전에 애니메이션이 되감겼다. 암반은 계속
  깎이는데 화면만 멈춰 있었다. 데미지 스텝과 보이는 스윙을 별도 시계로 분리했다. (D-063)
- **광차 구매 대부분이 갱도에서 보이지 않았다.** 앱 광차 수가 `EquipmentEngine.visualTier`
  기반이라 레벨 5와 15에서만 늘었다. 그 사이의 모든 광차 강화는 숫자만 바꾸고 장면은 그대로였다.
  `MineInfrastructureEngine`이 레벨 두 칸마다 한 대씩 파생하도록 교체했다. (D-064)
- **장비 아트 티어 계약 테스트가 피벗 이후 계속 실패하고 있었다.** 테스트가 세션 시절 경계
  20/40/60을 기대했으나 `visualTier`는 클리커 피벗에서 4/14로 옮겼다. 전체 `DeepMineAppTests`가
  "미검증(`Mach error -308`, 환경 문제)"로 분류돼 있어 이 제품 assertion 실패가 가려져 있었다.
  스위트는 정상 완주하며, 수정 후 134/134다.
- **웹 프로토타입과 앱이 서로 다른 경제를 돌리고 있었다.** 내구·탭·자동화·비용 지수·크리티컬·
  티어 경계·초기 장비·층 광석이 모두 달랐다. 웹에서 확인한 완료 ETA·보상 리듬·추천 강화
  타이밍은 앱으로 옮겨도 재현되지 않는 값이었다. Core를 진리로 두고 웹이 `coreBalance.ts`
  한 파일에서 읽도록 통일한 뒤, Swift 소스를 파싱해 대조하는 패리티 테스트로 고정했다. (D-061)

- **광부가 내려가지 않고 같은 자리에서 사각 암반만 반복 파괴했다.** 4m마다 별도 밴드를
  만들고 위에서 덮는 와이프를 초기화해 진행이 공간에 누적되지 않았다. 심도→y 연속 좌표,
  움직이는 굴착 헤드, 지역 단위 지층, 보어 이력으로 교체했다. (D-050)
- **심도표가 갱도 전체를 오른쪽으로 밀었다.** 눈금용 열을 `HStack` 폭으로 예약해 중심 보어가
  화면 중심과 달랐다. 눈금을 장면 위 좌측 오버레이로 바꿨다. (D-050)
- **강화가 숫자에만 존재했다.** 드릴·광차·램프를 올려도 램프 시야를 제외한 장면이 같았다.
  보어 폭·도구·파편·스윙, 레일·왕복 대수·속도·적재량, 설비·조사 거리·약점 광택을 같은
  장비 상태에서 파생한다. 분기 선택도 저장과 화면에 연결했다. (D-051)
- **피벗 이전 약속 UI가 클리커 홈의 위계를 차지했다.** 다음 약속·다음 세 걸음·연속 일수와
  중복 장면이 갱도보다 제품 정체성을 크게 말했다. 기본 홈에서 제거하고 집중은 접힌 선택
  패널로 격리했으며, 귀환의 다음 약속은 다음 굴착 목표로 재명명했다
- **지표에서 광부가 잘렸다.** `topDepth`를 0으로 고정하면서 0~23m의 헤드 y도 화면 상단에
  붙었다. 음수 암반을 만들지 않고 부족한 위쪽 24m를 열린 지표 갱도 inset으로 보충해 얕은
  구간과 깊은 구간 모두 같은 작업선에서 하강하게 했다
- **프레스티지 뒤 이미 연 장비 레벨이 다시 잠겼다.** 화면은 최고 심도를 표시했지만
  `EquipmentEngine`은 현재 위치로 상한을 계산했다. 지표로 돌아온 직후 6레벨부터 구매가
  거부됐다. 상한의 진실 공급원을 `recordDepthMeters`로 통일했다. (D-049)
- **오프라인 정산 뒤 같은 배경 시간이 화면에서 다시 지급될 수 있었다.** 수령 시트가
  `lastSettledAt`을 갱신해도 foreground 타이머는 오래된 로컬 시각을 시작점으로 사용했다.
  두 시각 중 더 최근 값을 읽도록 고치고 stale timer 회귀를 추가했다. (D-049)
- **심연 보너스가 HUD와 실제 암반을 갈랐다.** `bonusDepthMeters`가 보이는 심도만 더해
  막장 인덱스·암반 지역은 이전 위치에 남았다. 보너스를 실제 세그먼트 건너뛰기로 정규화하고

- **정사각 암반 타일 반복이 지역과 깊이를 지웠다.** 좌우 반전과 반 칸 어긋내기로도 같은

  생성하고 배경·구조·광맥 상태의 소비 역할을 분리했다. (D-048)

  `lastSettledAt`이 SwiftData 스키마에 아예 없었다. 앱을 껐다 켜면 심도가 0으로 돌아가고
  파던 암반과 오프라인 정산 기준 시각이 사라졌다. 전체 왕복 테스트가 이 필드들을 기본값
  0으로 두고 비교해 회귀를 잡지 못했고, 실제 값을 넣도록 함께 고쳤다.
- **진행이 지수적으로 정체해 게임을 끝까지 플레이할 수 없었다.** 암반 내구가 세그먼트당

  막혔다. 지역 4종 중 2종이 도달 불가였다. 세 원인을 함께 수정했다. (D-044)
- **프레스티지가 집중 세션 전용이었다.** 자격이 `runFocusCredits >= 40`이고 이 값은 세션
  완료로만 오른다. Screen Time 권한이 없는 플레이어는 프레스티지·코어 조각·영구 강화가
  영구히 잠겼다. 부순 암반 기준으로 바꿨다. (D-045)
- **프레스티지 직후 진행이 멈췄다.** 장비만 초기화하고 위치를 유지해서, 레벨 1 장비로
  300번째 세그먼트를 마주하게 됐다. 90일 시뮬에서 한 페르소나가 60일간 심도 1,200m에
  고정됐다. 위치를 지표로 되돌리고 최고 심도를 따로 보존한다. (D-046)
- **도전과제가 클리커 경로에서 평가되지 않았다.** 세션 완료·장비 구매·프레스티지에서만
  호출돼, 탭으로 이미 지나온 심도의 배지를 받을 수 없었다. 암반 파괴 시 평가한다. (D-047)
- **탭으로 넣은 데미지가 저장되지 않았다.** 세그먼트가 깨질 때만 저장해서, 수천 탭이 드는

  저장한다.
- **광차 미보유 시 임팩트 미터가 감쇠하지 않았다.** 자동화 틱의 `guard power.isAutomated`가
  틱 전체를 건너뛰어 감쇠까지 막았다. 14탭 후 화면을 떠날 때까지 데미지가 2배로 고정됐다.
- **밸런스 시뮬레이터가 실재하지 않는 게임을 모델링했다.** 하루 86,400초를 무제한 자동화로
  정산해 실제(8시간 캡 × 효율 0.75)보다 4배 후했고, 탭 수입은 0으로 뒀다. 이 위에서 나온
  증폭기 대역 판정은 근거가 없었다.

이전 단계에서 수정한 결함:

  19레벨의 상대 이득이 +3.6%, 회수 1,094세션이었다. 복리 효과와 `1.34^n` 비용, 심도 해금
  상한 60으로 교체했다. (D-023)
- 프레스티지가 run 기준 심도를 초기화해, 하루 100분 페르소나가 하루 25분 페르소나보다 낮은
  심도와 낮은 장비를 보이는 역전이 발생했다. 심도를 lifetime 기준으로 전환했다. (D-024)
- 프레스티지가 순손실이었다. 1회차 조각 1개로 최대 ×21 복리 장비를 초기화했다. 굴착 기억
  재구매 할인 50%와 run 크레딧 비례 조각으로 교체했다. (D-025)
- Dynamic Island/위젯의 시작·포기 버튼이 App Group 큐에만 기록하고 앱이 foreground가 될
  때까지 아무 일도 하지 않았다. 차단·알람·Live Activity가 시작되지 않고, 포기 버튼은 차단을
  유지한 채 남겼다. Live Activity intent가 앱 프로세스에서 즉시 명령을 적용한다. (D-027)
- 시계 무결성이 `ProcessInfo.systemUptime`(슬립 중 정지)을 써서, 화면을 끄고 진행한 정직한
  세션이 30초 임계를 넘겨 개방 채굴로 강등될 수 있었다. `CLOCK_MONOTONIC_RAW`로 교체했다.
- 스트릭 감쇠가 결석일마다 절반씩 누적되어 2주 공백이 실질 초기화였다. Spec §7.2가 거부한
  동작이다. 결석 1회당 감쇠 1회로 바꾸고 감쇠를 보상 계산 전에 확정한다.
- 중도 귀환이 공명 광맥의 다음 세션 ×2를 소진했다. 심층 포기(광석 0)에서도 소진됐다.
  완료한 세션에서만 소진한다.
- 추천 강화가 푸른 광맥만 계산해 램프의 기대 가치를 0으로 평가했다. 공명·수정·금고·심연을
  포함한 기대 광석으로 교체했다.
- 귀환 보고서의 등급 배지가 `state.completed`("준비 완료")를 재사용해 완료 화면에서 준비
  상태 문구를 보였다. 등급별 문구로 교체했다.
- `dailyRecords`가 무제한 증가해 장기 사용자의 매 저장이 전체 배열을 인코딩했다. 730일 상한.
- 탐사 갱도의 유일한 이점인 광맥 확률 3배가 어느 화면에도 없어 항상 열등한 선택으로 보였다.
- 연속 일수와 휴광일이 앱의 어떤 화면에도 표시되지 않았다. `game.streak` 등 관련 문자열이
  정의만 되어 있었다.

- 대형 500-history fixture가 통계 캡처를 지연시키던 문제를 대표 populated fixture로 분리했다. 500-history overflow 자체는 별도 UI 회귀 테스트로 유지한다.
- 격리 UI fixture가 제품 App Group 명령 큐를 drain해 관련 없는 복구 경고를 띄울 수 있던 문제를 차단했다.
- 귀환 보고서 소비 뒤 passive snapshot이 완료 상태에 남던 문제를 clear→waiting 게시 계약으로 수정했다.
- widget의 stale/missing 상태가 가짜 0 수치를 보이던 문제를 명시적 앱 열기 복구 상태로 교체했다.

## Open physical-device release gates

아래는 확정 결함이 아니라 시뮬레이터가 증명할 수 없는 위험이며, 통과 전 출시를 막는다.

| ID | 심각도 | 상태 | 항목 |
|---|---|---|---|
| GATE-001 | Critical | 미검증 | 승인 FamilyControls/App Group entitlement와 실제 차단·공유 컨테이너 |
| GATE-002 | Critical | 미검증 | AlarmKit과 커스텀 Live Activity의 실제 Dynamic Island 동시 운용 |
| GATE-003 | High | 미검증 | 앱 종료·재부팅·stale monitor에서 shield가 남지 않는지 |
| GATE-004 | High | 미검증 | 실제 extension→app 명령 큐 왕복과 applying crash window |
| GATE-005 | High | 미검증 | 잠금화면 Live Activity의 시스템 합성·크롭·수명주기 |
| GATE-006 | Medium | 미검증 | 실제 VoiceOver, Reduce Motion, Increase Contrast, 햅틱·사운드 체감 |

## Known non-blocking development signal

Xcode 26.5 UI test 로그의 `DebuggerVersionStore`/`no debugger version` 진단은 테스트 launch마다 출력되지만 성공 여부와 무관한 Xcode 환경 메시지다. 제품 오류로 분류하지 않는다.
